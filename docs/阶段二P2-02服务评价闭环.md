# 阶段二 P2-02 服务评价闭环

> 执行日期：2026-08-19
>
> 覆盖需求：服务关闭后邀请、匿名策略、1–5 星提交、低分质量跟进
>
> 数据边界：仅使用固定测试记录，不包含真实个人数据或医疗结论
>
> 任务结果：咨询关闭、移动评价、匿名质量查看、低分待办和上级核查闭环完成

## 1. 范围与非范围

### 1.1 本任务范围

- 每次咨询关闭事实独立生成一条站内评价邀请；重开不覆盖旧邀请，再次关闭形成新的服务轮次。
- 康养用户在已有受限会话中查看本人邀请，提交 1–5 星和可选补充意见。
- 工作人员侧采用 `STAFF_ANONYMOUS_SYSTEM_LINKED`：页面与员工 DTO 只显示匿名编号，不返回用户、咨询或服务责任人关联。
- 固定策略版本用于验证 7 天有效期和 `rating <= 2` 的低分跟进；邀请冻结关闭时生效的策略快照。
- 低分在同一事务中创建质量跟进和统一待办，由同机构上级接收、核查并解决。
- 解决前必须明确确认“单条评价不能直接形成对工作人员的结论”。

### 1.2 本任务非范围

- 不接入电话评价、录音、语音转写或外部邀请发送。
- 不启用真实短信、真实人员/组织/个人数据或面向用户的 AI。
- 不提供自动回复、医疗解释、诊断、治疗建议或其他医疗内容。
- 不建立正式运营排行、人员绩效结论或自动奖惩。
- 不把固定有效期和低分阈值作为正式业务配置；正式口径仍需业务方审批。
- 不提前实现 P2-03 通知 adapter、P2-04 完整运营看板或 P2-05 数据生命周期。

## 2. 模块归属与事务 seam

评价属于 `supervision` 质量域，咨询仍属于 `caseWork`。依赖方向保持单向：`caseWork` 只声明 `ConsultationClosedProjector` port，组合入口把 `SupervisionService` 注入实现。

咨询关闭事务按以下顺序执行：

1. 校验责任、状态、关闭理由和乐观锁版本；
2. 更新咨询并追加关闭互动、完成咨询待办、写入关闭 outbox；
3. 调用评价投影器，根据关闭事件和当时策略创建邀请及评价 outbox；
4. 写入咨询命令凭据并一起提交。

任一步失败都会回滚咨询关闭和评价投影，避免“服务已关闭但邀请事实丢失”的半成品。补偿扫描只处理已有关闭事实，并以 `sourceType + sourceEventId` 唯一约束保证重复执行安全。

## 3. 数据模型与不变量

| 表 | 职责 | 关键约束 |
| --- | --- | --- |
| `satisfaction_policies` | 不可变策略版本 | `code + version` 唯一；触发类型、生效时间、匿名方式、有效期、低分阈值冻结 |
| `satisfaction_requests` | 一次服务关闭对应的评价窗口 | `source_type + source_event_id` 唯一；保存策略快照、服务系统关联、邀请/到期/提交时间和版本 |
| `satisfaction_responses` | 用户评价事实 | 每个 request 唯一；星级 1–5；保存幂等键与请求摘要 |
| `satisfaction_follow_ups` | 低分质量跟进聚合 | 每个 request/response 唯一；保存机构、质量责任上级、状态和核查结果 |
| `satisfaction_follow_up_actions` | 跟进动作时间线 | 只追加；按操作者、操作和幂等键唯一；保存前后状态、版本和边界确认 |

内部 request 保留系统完成授权核查所需的用户、服务和机构关联；客户端 DTO 只返回本人邀请，员工 DTO 则主动省略这些关联。匿名展示不是删除审计关联，也不能绕过 DataScope。

## 4. 状态与幂等

### 4.1 评价邀请

`PENDING → SUBMITTED` 或 `PENDING → EXPIRED`

- 关闭时立即创建邀请；关闭发生时间加策略有效期得到 `expiresAt`。
- 列表、详情和提交前都会惰性推进已到期的 `PENDING` 邀请。
- 每个邀请只能创建一条 response；相同键和相同请求重放原结果，相同键不同内容返回幂等冲突，其他重复提交返回已提交。
- 高分只完成评价；达到低分条件时，在评价提交事务中同步创建质量跟进、活动待办和 outbox。

### 4.2 质量跟进

`OPEN → IN_REVIEW → RESOLVED`

- `OPEN`：等待指定上级接收；没有可用上级时保留未分配跟进，不伪造责任人。
- `IN_REVIEW`：当前责任上级已接收并记录核查安排。
- `RESOLVED`：当前责任上级记录事实性核查结果，可附加流程改进动作；同一事务完成活动待办。
- 接收和解决均要求 `Idempotency-Key`、`expectedVersion` 和状态/责任校验。

## 5. 接口契约

### 5.1 康养用户受限会话

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/care/client/satisfaction-requests` | 查询本人评价邀请分页 |
| `GET` | `/care/client/satisfaction-requests/{id}` | 查询本人邀请与已提交响应 |
| `POST` | `/care/client/satisfaction-requests/{id}/responses` | 幂等提交 1–5 星和补充意见 |

写接口继续执行受限会话认证和严格同源校验；请求不接受外部用户、机构、咨询或服务责任人 ID。

### 5.2 上级员工端

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/care/satisfaction-responses` | 查询机构内匿名评价，可按星级/跟进状态筛选 |
| `GET` | `/care/satisfaction-follow-ups` | 查询低分质量跟进分页 |
| `GET` | `/care/satisfaction-follow-ups/{id}` | 查询匿名评价、质量责任人与动作时间线 |
| `POST` | `/care/satisfaction-follow-ups/{id}/acknowledge` | 当前责任上级接收跟进 |
| `POST` | `/care/satisfaction-follow-ups/{id}/resolve` | 当前责任上级解决跟进并确认使用边界 |

所有分页保持 `{ page, pageSize, total, list }`；Swagger `@Success` 使用具体 DTO。

## 6. 权限与匿名边界

- 康养用户只能访问当前受限会话绑定的本人 request；跨用户 ID 返回失败关闭结果。
- 五个员工 API、`CareSatisfaction` 菜单和三个操作按钮只授予 `SUPERVISOR`。
- 上级还必须通过业务身份、DataScope 和机构校验；跨机构、管家、医护、内容管理员、普通管理员和缺身份请求全部拒绝。
- 匿名评价列表/详情不返回 `careClientId`、`sourceId`、`sourceEventId`、`serviceAssigneeId` 或服务责任角色。
- 跟进页显示的责任人仅是质量核查责任上级，不是被评价的服务人员。
- 页面按钮只控制入口；后端独立执行授权、状态、责任、版本和幂等校验。

## 7. 迁移、初始化与回退

- `bizModel()` 通过 AutoMigrate 登记五张评价表；不会删除或覆盖历史表。
- 固定记录开关启用时，初始化幂等创建 `CONSULTATION-CLOSE-TEST v1` 策略、员工 API、菜单、按钮与上级权限。
- 策略只用于当前工程验证：有效期 168 小时、低分阈值 2、员工侧匿名展示；正式值未获批准前不提供普通后台修改入口。
- 回退代码提交不会自动删除评价、跟进、动作、待办或 outbox；物理删除需要单独审批与备份。

## 8. 前端交付

- 移动端在“我的任务”增加服务评价入口，提供邀请列表、星级表单、补充意见、已提交回显与到期提示。
- 客户端把评价提交幂等键保存在会话本地状态；网络响应丢失后可使用同一键安全重试，成功后清理。
- 上级端提供匿名评价与低分跟进两个列表、筛选、详情抽屉、接收和解决对话框。
- 解决对话框必须勾选单条评价使用边界；页面不出现用户、咨询或服务责任人关联。
- 页面使用 UnoCSS 原子类和现有主题 token，没有新增 scoped CSS 或内联样式。

## 10. 未决输入

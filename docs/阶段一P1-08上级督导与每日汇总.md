# 阶段一 P1-08 上级督导与每日汇总

## 范围

- 为授权上级提供今日实时汇总、历史日报版本和重点事项快照。
- 提供管理范围内的复核队列，并投影待处理、已指导、已介入和已完成状态。
- 支持追加上级指导、安排讨论和直接介入，明确后续责任医护与完成时限。
- 指导/介入与事项行动、活动待办和 outbox 事实在同一事务内提交。
- 登记督导中心菜单、页面按钮、五个 API 元数据和上级角色策略。

## 非范围

- 不启用正式日报定时任务，也不提供人工生成日报的 HTTP 接口。
- 不实现通知尝试、通道回执、补发或通知异常待办写入；这些由 P1-09 完成。
- 不完成所有角色默认首页、完整菜单矩阵和全场景隔离；这些由 P1-10 收口。
- 不修改原答卷、规则命中或下级行动，不生成医疗结论，不启用真实短信或面向用户的 AI。
- 按阶段规则不执行页面点触，集中验收留到 P1-11。

## 数据模型

### `daily_summary_versions`

| 字段组 | 含义 |
| --- | --- |
| `organizationId + businessDate + version` | 不可变版本唯一键 |
| `metricDefinitionVersion + generatedAt` | 统计口径版本和生成时间 |
| 七项整数指标 | 服务人数、应执行、已提交、送达异常、未关闭、当日解决、待上级复核 |
| `focusCasesJSON` | 生成时冻结的重点事项摘要 |
| 公共操作字段 | 部门范围、创建人和固定测试门禁 |

同一业务日的修正生成 `version + 1`，旧版本不更新、不删除。

### `supervisor_guidance`

每条记录关联一个 `CaseAction`，保存动作类型、指导或介入内容、操作者、责任医护、截止时间、事项前后版本、发生时间及幂等摘要。记录只追加，不承载覆盖式备注。

复核队列不新增表；它由关注事项、请求上级复核的医护行动、上级指导/介入事实和后续行动实时投影。

## 状态

| 复核投影 | 含义 |
| --- | --- |
| `PENDING` | 最近一次请求上级复核后尚无上级动作 |
| `GUIDED` | 最近上级动作是指导，事项仍等待复核 |
| `INTERVENED` | 最近上级动作是介入，事项已回到处理中 |
| `COMPLETED` | 上级动作后已有后续处理或事项离开该复核周期 |

指导和讨论安排保持 `WAITING_SUPERVISOR`；直接介入进入 `HANDLING`。两者都保持唯一活动待办开放，并更新责任医护、截止时间和版本。指导后再次请求复核会形成新的 `PENDING` 周期。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/care/daily-summaries` | 分页读取今日实时预览和历史版本 |
| GET | `/care/daily-summaries/{id}` | 读取历史版本与重点事项快照 |
| GET | `/care/reviews` | 分页读取复核队列 |
| POST | `/care/reviews/{id}/guidance` | 追加指导或讨论安排 |
| POST | `/care/reviews/{id}/intervene` | 记录直接介入 |

列表保持 `{ page, pageSize, total, list }`，所有响应保持 `{ code, data, msg }`。写接口要求 `Idempotency-Key` 与 `expectedVersion`。

## 权限

- 只有业务角色 `SUPERVISOR` 获得督导中心菜单、按钮和五个 API 策略。
- 上级读取与写入都必须落在其 DataScope 可见部门和归属机构内。
- 管家、医护、普通管理员、跨机构人员及缺少业务身份的请求均失败关闭。
- 关注事项详情先授权聚合，再读取其完整行动历史；子事实查询不能作为独立扩权入口。

## 迁移与初始化

- GORM 自动迁移新增 `daily_summary_versions` 和 `supervisor_guidance`。
- 初始化幂等登记“督导中心 / 每日汇总 / 待复核事项”菜单和 `viewDetail`、`guide`、`discuss`、`intervene` 按钮。
- 固定测试开关启用时，仅在目标业务日没有版本时创建一条历史快照；重复启动不会重复写入。
- 当前不创建定时任务，也不连接外部通知或 AI 服务。

## 关键测试与证据

- 固定时钟验证七项实时指标、闭环后重算、历史 v1/v2 修正与旧版本不可变。
- 验证跨机构无法读取日报或操作事项，管家无法调用督导动作，无效责任医护被拒绝。
- 验证指导/介入的事项行动、指导记录、活动待办和 outbox 原子提交，以及相同命令重放、不同请求冲突和过期版本冲突。
- 验证指导后再次请求复核会回到 `PENDING`，直接介入投影为 `INTERVENED`。
- 验证 API、路由、菜单、按钮和 Casbin 策略幂等且只授予上级角色。
- 前端每日汇总与复核页面使用语义化主题 token 和 UnoCSS 原子类，不增加自定义样式层。

## 1. 使用方法

本清单是项目负责人的执行入口。请从上到下逐项完成，不要同时启动多个互相依赖的业务任务。

每个开发任务都遵循同一节奏：

```text
项目负责人选择一个任务
→ Codex 读取项目规则并提出计划
→ 项目负责人确认范围、权限和验收方式
→ Codex 实现、测试和浏览器验证
→ 项目负责人验收业务结果
→ Codex 更新文档并创建一个 Git 提交
→ 进入下一个任务
```

勾选规则：

- `[x]`：已经完成并有证据；
- `[ ]`：尚未完成；
- 只有代码、测试、页面点触和 Git 提交全部完成，才能把开发任务改为 `[x]`；
- 正式医疗内容、真实数据、正式通知和 AI 能力未获授权时，保持禁用，不阻塞通用工程继续开发；
- 不用为了赶演示日期并行铺开多个未闭环模块。

## 2. 你与 Codex 的职责边界

### 2.1 你必须决定或确认

- 功能优先级、阶段范围和是否接受范围变化；
- 业务流程是否符合真实工作方式；
- 管家、医护、上级、机构人员分别能看什么、做什么；
- 验收场景、验收账号和预期结果；

- 是否执行数据删除、批量迁移、`make reset`、推送远程、合并或发布；
- 每个功能是否可以结束并进入下一个功能。

### 2.2 可以直接交给 Codex

- 阅读 `AGENTS.md`、`aiDoc`、R2、架构和源码；
- 细化一个已选功能的字段、状态、接口和错误码；
- 按项目规范实现后端、前端、测试和 Swagger；
- 使用合成数据完成自动测试和浏览器点触；
- 检查菜单、按钮、API、DataScope 和业务责任关系；
- 更新对应业务记忆、架构决策和开发文档；
- 检查 Git diff、排除凭证并整理单功能提交。

### 2.3 Codex 必须暂停并等待你的情况

- 需要新增或改变已经确认的业务范围；
- 需求存在两种会明显改变用户体验或数据模型的解释；
- 需要编写、修改或启用医疗规则和阈值；
- 需要接触真实人员、真实联系方式或真实健康数据；
- 需要向真实用户发送消息或调用收费外部服务；
- 需要扩大某个角色的数据权限；
- 需要删除数据、重建卷、覆盖历史、强制推送或部署；
- 验收结果与 R2、架构说明或你的预期不一致。

# 阶段二 P2-07 UAT、培训、灰度与回滚演练

> 执行日期：2026-08-19
>
> 覆盖任务：UAT 准备、角色培训、灰度门禁、暂停与回滚桌面演练
>
> 数据边界：仅使用固定测试范围，不记录真实身份、联系方式、账号或凭据
>
> 任务结果：机器契约、培训/UAT 清单和无副作用桌面演练完成；真实试用、部署、备份恢复和对外能力继续保持关闭

## 1. 范围与非范围

### 1.1 本任务范围

- 建立 `P2-07-v1` 机器可读演练契约，固定环境、数据范围、能力开关和外部门禁。
- 准备阶段二十条 UAT 用例，覆盖 P2-01～P2-06 与关键负向分支。
- 准备客户受限会话、管家、医护、上级、内容管理员和普通管理员负向边界的培训提纲。
- 冻结缺陷分级、灰度进入/暂停条件、回滚原则和证据记录字段。
- 以无网络、无部署、无数据库写入的桌面序列验证 promotion 被拒绝、暂停和回滚决策可追踪。
- 增加 `make phase2-rehearsal-check`，用严格 JSON 解码验证所有安全不变量。

### 1.2 本任务非范围

- 不开展真实人员 UAT 或培训，不建立试用名单、批次、比例、时长或正式排班。
- 不启用真实用户、真实身份、正式同意、正式内容、真实短信、工作人员影子或面向用户的 AI。
- 不部署、不切换流量、不改 DNS/网关、不变更容器、不停止服务。
- 不执行数据库备份、恢复、迁移回退、卷重置、Git 回退或历史改写。
- 不新增业务数据库、HTTP/Swagger、页面、菜单、按钮或权限。
- 不做页面点触、全仓回归、Compose 重建/重启或 P2-08 集中验收。
- 不把本地 Compose 健康状态解释为生产可用性或真实试用准备完成。

## 2. 歧义处理与安全决策

P2-07 同时提到 UAT、培训、灰度和回滚，但真实试用范围、正式内容、身份与同意、通知供应商、SLA、容量、监控/安全事件责任人、备份 RPO/RTO 和恢复批准均为空。当前本地容器健康只说明开发环境可用，不提供真实部署授权。

直接创建试用批次或执行恢复会产生真实外部影响，且需要明确环境、对象、备份和恢复方案。因此本任务暂停向实际操作延伸，并采用以下边界：

1. “演练”仅指版控契约和决策桌面推演，不调用 Docker、数据库、网络或外部系统；
2. UAT 与培训在 P2-07 只达到“材料准备完成”，实际执行统一留到 P2-08；
3. 所有外部门禁缺失时，promotion 必须失败关闭；
4. 回滚默认只考虑代码回退并保留业务数据，任何数据恢复或删除另行授权；
5. 后续真实试用不得复用本契约中的 `LOCAL_TEST` 标识冒充已批准环境。

## 3. 数据模型、接口、权限与迁移

- 数据模型：无持久化模型。`docs/contracts/phase2-rehearsal.json` 是版控运维契约，不是业务表。
- 状态：仅有桌面演练状态，不写入服务端或数据库。
- 接口：无新增 HTTP、Swagger 或前端调用；Makefile 入口只运行 Go 契约测试。
- 权限：无菜单、按钮、Casbin、DataScope 或角色范围变化。
- 迁移：无表、列、索引、配置卷或数据回填；不需要数据库回退。

## 4. 机器契约与关闭门禁

契约头固定为：

```text
schemaVersion=P2-07-v1
environment=LOCAL_TEST
dataScope=FIXED_TEST_ONLY
executionMode=TABLETOP
realTrialEnabled=false
promotionAllowed=false
```

以下能力全部固定关闭：

- 真实数据；
- 正式通知；
- 工作人员 AI 影子；
- 面向用户的 AI；
- 外部网络调用。

以下门禁必须逐项保留，不能以“继续开发”代替责任方确认：

| 门禁 | 当前状态 |
| --- | --- |
| 真实试用范围批准 | `BLOCKED` |
| 正式内容批准 | `BLOCKED` |
| 真实身份与同意制度 | `BLOCKED` |
| 正式通知能力 | `BLOCKED` |
| 服务 SLA | `BLOCKED` |
| 容量目标 | `BLOCKED` |
| 监控与安全事件责任人 | `BLOCKED` |
| 备份 RPO/RTO | `BLOCKED` |
| 恢复演练完成 | `BLOCKED` |
| 安全评审完成 | `BLOCKED` |

所有 owner 固定为 `UNASSIGNED`，避免以虚构姓名或角色制造批准结论。

## 5. UAT 用例准备

P2-07 只冻结用例和预期，所有执行状态为 `DEFERRED_TO_P2_08`：

| ID | 范围 | P2-08 关键预期 |
| --- | --- | --- |
| `P2-UAT-01` | 角色与机构边界 | 允许角色可见最小范围；跨机构、内容管理员运行态和普通管理员请求拒绝 |
| `P2-UAT-02` | 主动咨询 | 客户创建/补充，工作人员分配、回复、转交、升级、解决、关闭/重开可追踪 |
| `P2-UAT-03` | 评价与跟进 | 一次服务一次邀请/响应；匿名 DTO 不泄露关联；低分跟进不形成个人结论 |
| `P2-UAT-04` | 通知契约边界 | 回执状态、重试/限流/费用门禁正确，网络和正式发送仍关闭 |
| `P2-UAT-05` | 看板、日报与修正 | 十二项指标、自然日、最新版本、追加修正和跨机构隔离正确 |
| `P2-UAT-06` | 数据治理关闭态 | 真实数据/正式同意/执行关闭；固定测试请求仅为待政策事实 |
| `P2-UAT-07` | AI 关闭态 | 阶段二未选择；无生成、知识检索、外部模型、用户侧或直发能力 |
| `P2-UAT-08` | 恢复性业务动作 | 计划暂停/恢复、事项重开和咨询重开保留历史且版本正确 |
| `P2-UAT-09` | 幂等与重试 | 重复请求重放原结果，不同请求冲突，不产生重复业务对象 |
| `P2-UAT-10` | 无外部副作用 | 全流程不发送真实通知、不调用模型、不触碰真实数据 |

每次执行至少记录：用例 ID、Git 提交、环境标识、测试角色、开始/结束时间、结果、证据路径、缺陷 ID 和复核人。不得记录密码、会话值、真实身份或正文数据。

## 6. 培训提纲

### 6.1 客户受限会话

- 识别受限入口、任务和咨询/评价边界；
- 只操作当前会话允许的对象，不通过 URL 或 ID 扩大范围；
- 断网、刷新、重复提交或会话失效时保留/恢复流程；
- 成功提示仅代表记录已提交，不代表已经处理或送达。

### 6.2 管家

- 从工作台进入任务、关注事项和主动咨询；
- 区分联系记录、公开回复、转交和升级；
- 不使用医护或上级专属动作；
- 通知异常不得取消后续任务，正式发送门禁关闭时走人工流程。

### 6.3 医护

- 在责任范围内记录事项处理、协作和上级复核请求；
- 保留已有行动，不覆盖其他人员的历史记录；
- 咨询解决与事项关闭按各自状态和权限执行；
- 不把测试内容解释为正式结论。

### 6.4 上级

- 使用运营看板、日报、复核队列、评价跟进和历史修正；
- 区分实时预览、历史快照、最新版本和修正版；
- 数据治理与 AI 页面/接口只显示关闭态，不据此批准真实能力；
- 低分评价只触发质量跟进，不直接形成个人结论。

### 6.5 内容管理员

- 只读查看问卷和计划版本；
- 不访问客户、任务、咨询、评价、治理或督导运行数据；
- 当前没有内容发布写入口，不把测试版本冒充正式内容。

### 6.6 普通管理员负向边界

- 可管理基础系统不等于获得康养业务数据权限；
- 不应出现业务菜单、按钮或 `/care/**` Casbin 授权；
- 手工输入业务路由仍应由后端拒绝。

培训状态统一为 `PREPARED_NOT_DELIVERED`。实际参训人、时间、讲师、反馈和签字待真实试用责任方确认后再记录。

## 7. 缺陷分级与 promotion 门禁

| 等级 | 定义 | 处理 |
| --- | --- | --- |
| `BLOCKER` | 越权、真实外发、数据丢失/破坏、关键闭环错误或无法安全回退 | 立即暂停，禁止 promotion |
| `MAJOR` | 核心角色无法完成主流程，且没有安全替代方式 | 禁止 promotion，修复后重测 |
| `NORMAL` | 非核心流程异常或存在明确安全替代方式 | 登记负责人和计划，是否阻塞由验收人决定 |
| `MINOR` | 不影响行为和边界的展示问题 | 可排入后续修正，不得掩盖真实状态 |

只要存在未关闭的 `BLOCKER`、未处置的 `MAJOR`、任一外部门禁未完成或证据缺失，promotion 都必须保持关闭。当前契约无条件返回 `promotionAllowed=false`。

## 8. 灰度、暂停与回滚桌面演练

### 8.1 桌面状态

```text
HOLD
  -> BEGIN_DRY_RUN -> DRY_RUN
  -> PROMOTE       -> DENIED，保持 DRY_RUN
  -> PAUSE         -> DRY_RUN_PAUSED
  -> ROLLBACK      -> DRY_RUN_ROLLED_BACK
  -> VERIFY_AND_HOLD -> HOLD
```

该序列只验证决策人是否能识别阻塞、拒绝 promotion、暂停继续推进、选择保留数据的代码回退策略，并在核对后回到 `HOLD`。

### 8.2 暂停触发条件

以下任一情况都必须暂停：

- 角色或机构隔离失败；
- 产生真实通知、外部模型或其他未授权调用；
- 数据丢失、覆盖、错误删除或不可解释的版本变化；
- 关闭态能力被显示或解释为已启用；
- 主流程状态、幂等或审计事实不一致；
- 监控、事件责任人、备份或恢复证据缺失；
- 验收人撤回或未给出继续授权。

### 8.3 回滚原则

- 当前桌面策略为 `CODE_ONLY_RETAIN_DATA`；不执行任何命令。
- 真实回滚前必须记录精确环境、目标提交/镜像、配置版本、迁移兼容性、备份位置、恢复验证和责任人。
- 添加式迁移默认保留，不通过自动删表、清卷或覆盖历史来匹配旧代码。
- 数据库恢复、卷重置、Git 回退、部署和切流都属于单独高风险操作，必须使用明确授权模板。
- 回退后重新验证健康、迁移兼容、登录、角色边界、主流程、定时任务和外部能力关闭状态，再决定是否解除暂停。

# 阶段一 P1-03 问卷、答卷和关注规则版本

> 日期：2026-08-18
>
> 状态：实现、自动化与浏览器验收完成；待项目负责人验收和提交。
>
> 数据边界：定义、账号和验收数据全部为醒目标注的合成夹具；未加入真实个人数据、正式医疗内容、真实短信或面向康养用户的 AI。

## 1. 交付结论

P1-03 已实现不可变问卷版本、题目、选项和校验，规则版本生命周期与发布门禁，追加式答卷修订、冻结规则评估、规则命中快照和事务型 outbox；后台只开放问卷版本列表与详情预览。

本任务固定使用合成问卷版本 `9401` 和合成规则版本 `9501`。正式内容仍无种子、无写入口且保持门禁关闭。

## 2. 范围与非范围

### 2.1 本任务范围

- 普通 `questionnaire` package，不使用插件结构。
- 问卷版本、题目、选项、校验和规则版本的不可变定义。
- `DRAFT -> IN_REVIEW -> APPROVED -> PUBLISHED -> DISABLED` 单向生命周期。
- `TEST_ONLY` 与 `FORMAL` 两套发布/执行门禁及审核记录。
- 一个外部冻结任务标识对应一份提交；修订只追加、不覆盖。
- 只评估任务显式冻结的规则版本，保存命中条件、级别、原因和接收角色快照。
- 提交、命中与最小事务型 outbox；只记录 `TaskAnswerSubmitted`、`RuleHitRecorded`，不实现消费者。
- 后台问卷版本列表、详情预览、菜单、按钮、API、Casbin 和服务端角色校验。

### 2.2 本任务非范围

- 不创建 P1-04 的路径、计划或任务表；`taskId` 只是外部稳定标识，无外键。
- 不实现 P1-05 的康养用户移动端、受限会话、草稿或公开提交接口。
- 不创建 P1-06 的 `AttentionCase`、待办、确认、处置或关闭流程。
- 不提供问卷/规则创作、审核、发布或禁用的 HTTP/前端写入口。
- 不实现分支问卷、评分、导出、通知、真实短信或 AI。
- 不自动重评修订答卷，不撤销或替换旧 `RuleHit`。
- 不写入真实问卷、临床阈值、医疗判断或诊断内容。

## 3. 数据模型与迁移

迁移使用启动期增量 GORM `AutoMigrate`，新增九张表：

| 表 | 用途 | 关键约束 |
| --- | --- | --- |
| `questionnaire_versions` | 不可变问卷版本 | 编码 + 版本唯一；生命周期、范围、审核、定义哈希 |
| `questionnaire_questions` | 版本内题目 | 问卷版本 + 题目编码唯一；题型、顺序、校验 JSON |
| `questionnaire_options` | 题目选项 | 题目 + 选项编码唯一；稳定编码与顺序 |
| `questionnaire_rule_versions` | 关注规则版本 | 编码 + 版本唯一；冻结条件、级别、原因、接收角色与定义哈希 |
| `questionnaire_submissions` | 首次提交事实 | `task_id` 唯一；冻结问卷/规则、来源、操作人、当前修订号 |
| `questionnaire_answer_revisions` | 追加式答案历史 | 提交 + 修订号唯一；规范答案、原因、发生时间 |
| `questionnaire_rule_hits` | 规则命中快照 | 提交 + 规则 + 去重键唯一；绑定具体答案修订 |
| `questionnaire_command_receipts` | 写命令幂等回执 | 操作人 + 操作 + 幂等键唯一；请求哈希与首次结果 |
| `outbox_events` | 事务型领域事件 | 事件 ID 唯一；类型、聚合、载荷、关联和因果标识 |

定义表是全局内容配置，不带 `dept_id`。运行事实表带 `dept_id`、`created_by`，由统一 DataScope 上下文过滤和盖章，Service 不接受前端字段决定数据范围。

本任务迁移不删除、不重命名、不覆盖既有表。若开发环境需要恢复，只能在确认无后续依赖后由负责人明确授权移除上述新增表；常规回滚优先回退代码并保留数据。

## 4. 状态、门禁与不变量

### 4.1 内容生命周期

```text
DRAFT -> IN_REVIEW -> APPROVED -> PUBLISHED -> DISABLED
```

- 生命周期只能逐步前进，不允许回退或越级。
- 已发布定义由规范 JSON 的 SHA-256 定义哈希校验；MySQL 对 JSON 对象键重排不会改变哈希。
- 服务不暴露原地更新定义的入口；新内容必须创建新版本并可引用被替代版本。

### 4.2 使用范围和审核门禁

- `TEST_ONLY`：必须为合成内容、`productionEnabled=false`、工程复核，且本地合成夹具开关开启。
- `FORMAL`：必须为非合成内容、`productionEnabled=true`、正式复核。
- P1-03 不创建或启用任何 `FORMAL` 内容。
- 未发布或已禁用的冻结规则不执行；答卷仍能提交，并明确返回规则执行已禁用，不从当前规则集合补算。

### 4.3 答卷与修订

- 支持 `SINGLE_CHOICE`、`MULTIPLE_CHOICE`、`TEXT`、`NUMBER`、`DATE`、`BOOLEAN` 六种基础题型。
- 一个 `taskId` 最多一份 `QuestionnaireSubmission`。
- 首次提交创建修订号 `1`；更正通过 `expectedRevisionNo` 乐观锁新增下一修订。
- `STAFF_ASSISTED` 来源必须记录代填原因和确认方式。
- 修订不覆盖历史，不自动重评、撤销或替换既有规则命中。

### 4.4 规则冻结与事务

- 评估仅使用 `FrozenTaskBinding.boundRuleVersionIds`，不会扫描后来发布的规则。
- `RuleHit` 绑定产生它的 `AnswerRevision`，保存条件、级别、原因和接收角色快照。
- 首次提交、首版答案、规则命中、命令回执与 outbox 在同一数据库事务内完成；outbox 写入失败时全部回滚。
- P1-03 不实现 outbox 投递器或下游消费者。

## 5. 接口

后台接口复用 GVA 私有路由、JWT、MustChangePwdGuard、Casbin 和 DataScope，响应统一为 `{code,data,msg}`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/care/questionnaire-versions` | 按关键词、状态、使用范围、合成标记分页查询版本 |
| `GET` | `/care/questionnaire-versions/{id}` | 读取问卷、题目、选项、校验、审核和绑定规则快照 |

分页统一使用 `request.PageInfo` 和 `LimitOffset()`，最大 `pageSize=100`。静态契约见 [sleep-care-phase1.openapi.yaml](./contracts/sleep-care-phase1.openapi.yaml)，运行 Swagger 已同步到 `server/docs/`。

写侧仅提供 Go 服务组合接口：

- `RecordSubmission(ctx, frozenBinding, command)`；
- `AppendAnswerRevision(ctx, command)`。

本任务没有注册 POST/PUT/DELETE HTTP 路由。

## 6. 权限与数据隔离

| 角色 | 菜单/预览按钮 | 列表/详情 API | 写侧 HTTP |
| --- | --- | --- | --- |
| 合成一线医护 `9802` | 允许 | 允许 | 不存在 |
| 合成上级医师 `9803` | 允许 | 允许 | 不存在 |
| 合成健康管家 `9801` | 不授权 | HTTP 403 | 不存在 |
| 普通管理员 `888` | 不授权 | HTTP 403 | 不存在 |
| 缺身份/未映射角色 | 不授权 | 拒绝 | 不存在 |

菜单和按钮只用于界面体验；服务端 `internal/accesspolicy` 采用 fail-closed 领域角色判断，Casbin 继续限制 path + method。

三类合成业务角色只额外获得进入/退出后台所需的 `/menu/getMenu`、`/user/getUserInfo`、`/jwt/jsonInBlacklist` 最小壳层权限；这不授予问卷数据访问。问卷菜单、按钮和两个只读接口仍只授予医护与上级。

## 7. 合成夹具

仅在合成夹具开关显式启用时创建：

- 问卷版本 `9401`：发布态、`TEST_ONLY`、合成、工程复核、生产关闭；
- 一道不含医疗语义的软件流程验证题和两个合成选项；
- 规则版本 `9501`：发布态、`TEST_ONLY`、合成、工程复核、生产关闭；
- 医护/上级菜单、预览按钮与只读 API 权限。

种子严格且幂等：固定 ID 被其他记录占用、定义哈希或子项内容不一致时启动失败，不覆盖现有内容。夹具开关关闭时只迁移表和权限元数据，不创建内容行。

## 8. 前端页面

动态菜单组件为 `view/sleep-care/questionnaires/index.vue`，组件名为 `CareQuestionnaires`。页面提供：

- 合成/测试内容醒目标识；
- 关键词、状态、使用范围和合成标记筛选；
- 分页、loading、空状态和错误反馈；
- 详情抽屉中的审核记录、生产门禁、题目、选项、校验与规则快照；
- 只读说明，不显示发布、编辑、填写或医疗处置操作。

页面通过 `web/src/api/sleep-care/questionnaires.js` 调用统一请求封装，样式使用 UnoCSS 原子类。

## 10. 风险与后续边界

- P1-03 的内部提交服务尚未接入任务或移动受限会话；这是有意边界，不是公开能力缺失。
- 当前规则评估器只实现合成夹具所需的基础运算符，不构成正式医疗规则引擎。
- 正式题目、阈值、级别、合并策略、SLA、审核人和生产门禁未确认前，继续保持无正式内容、无正式入口。
- 项目负责人验收完成前不创建提交；不得自动开始 P1-04。

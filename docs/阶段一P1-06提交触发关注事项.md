# 阶段一 P1-06 提交触发关注事项

## 范围

- 客户端提交命中已发布 `TEST_ONLY` 规则后，原子创建 `AttentionCase`、活动 `TodoItem` 和 outbox 事实。
- 员工端后端提供事项分页、详情、确认、联系/处置、升级、关闭和主管重开接口。
- 保存追加式行动时间线、乐观锁版本和幂等回执。
- 对历史测试 `RuleHit` 提供受开关控制、可重复运行的补偿。

## 非范围

- 不新增员工菜单、按钮、列表或详情页面；这些由 P1-07 实现。
- 不实现上级指导/介入和每日汇总；这些由 P1-08 实现。
- 不启用正式关注等级、SLA、真实短信、正式身份认证或面向用户的 AI。
- 不修改原始答卷，不从答案生成医疗结论。

## 数据模型

| 对象 | 用途 | 关键约束 |
| --- | --- | --- |
| `AttentionCase` | 规则命中产生的关注事项聚合 | `sourceType + sourceRuleHitId + dedupKey` 唯一；版本号乐观锁；标准部门归属字段 |
| `CaseAction` | 确认、联系、处置、升级、解决、关闭、重开的追加事实 | 保存操作者、角色、机构/团队、结果、理由、前后状态和时间；不覆盖历史 |
| `TodoItem` | 当前责任人的统一业务待办 | 同一事项最多一条 `ACTIVE`；历史待办通过完成或替代状态保留 |
| `CommandReceipt` | 员工动作幂等回执 | 操作者、操作、幂等键摘要唯一；只保存摘要和响应快照 |

## 状态与动作

```text
PENDING_ACK -> ACKNOWLEDGED -> HANDLING / WAITING_*
WAITING_* -> HANDLING -> RESOLVED -> CLOSED
CLOSED --主管重开--> HANDLING
```

- 管家可确认、写 `CONTACT`、升级至当前有效责任医护。
- 当前责任医护可确认、写 `HANDLING`、升级、解决并关闭。
- 授权主管可在管理范围内关闭已解决事项并重开已关闭事项。
- 关闭必须同时满足 `RESOLVED`、非空处理结果、非空关闭理由和最新版本。
- 重开保留全部行动，清空上一轮处理结果/关闭字段，并为原责任人创建新待办。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/care/attention-cases` | 授权范围分页；`status`、`assigneeId` 只能缩小范围 |
| GET | `/care/attention-cases/{id}` | 最小事项详情、命中快照和行动时间线 |
| POST | `/care/attention-cases/{id}/acknowledge` | 确认事项 |
| POST | `/care/attention-cases/{id}/handling-records` | 按角色追加 `CONTACT` 或 `HANDLING` |
| POST | `/care/attention-cases/{id}/escalate` | 转交到有效责任医护并替换活动待办 |
| POST | `/care/attention-cases/{id}/close` | 完整结果和理由后关闭 |
| POST | `/care/attention-cases/{id}/reopen` | 主管重开并产生新待办 |

写接口统一要求 `Idempotency-Key` 和 `expectedVersion`，响应保持 `{code,data,msg}`。

## 权限

- 员工请求先通过标准 JWT、强制改密、Casbin 与 DataScope 链。
- 主管依部门管理范围读取；管家和医护还必须对事项所属用户具有当前有效责任关系。
- 动作再校验角色与当前事项责任人。筛选参数、路径 ID 和同机构关系都不能扩大范围。
- 普通管理员、受限客户端会话、跨部门人员和无责任人员不能访问员工事项接口。

## 迁移与补偿

- `gorm_biz.go` 迁移四张 casework 表及唯一索引。
- 初始化登记七条 API 与最小 Casbin 权限，不创建 P1-07 的菜单或按钮。
- 固定测试开关开启时，仅扫描测试 `RuleHit` 中尚无事项的记录，复用正常创建服务补齐事项、待办和 outbox；开关关闭时完全跳过。

## 关键测试

- 提交命中规则产生且只产生一条事项、一个活动待办和一个打开事件；重复提交返回原事项。
- 缺少有效责任管家时，答卷、规则命中、事项、待办和任务状态原子回滚。
- 确认幂等、幂等键改参冲突、过期版本冲突。
- 管家不能写专业处置；医护完成处理后才能关闭；上一轮结果不能在重开后直接复用。
- 无身份、无责任关系和跨部门详情查询失败关闭；列表只返回授权范围。
- 历史命中补偿受开关控制且重复运行无新增记录。
- 七条路由与 Casbin 角色矩阵一致；不执行页面点触。

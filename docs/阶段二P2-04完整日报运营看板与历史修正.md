# 阶段二 P2-04 完整日报、运营看板与历史修正

> 执行日期：2026-08-19
>
> 覆盖需求：机构级完整日报、最近七日运营概览、前一日自动快照和历史追加修正
>
> 数据边界：仅使用固定测试记录，不包含真实个人数据或医疗内容
>
> 任务结果：`P2-04-v2` 测试口径与自动化链路完成；正式报表、人员/团队归属、真实短信和面向用户的 AI 保持关闭

## 1. 范围与非范围

### 1.1 本任务范围

- 把原七项每日汇总扩展为十二项机构级指标，并显式返回指标定义版本、生成方式和统计截止时间。
- 保留今日实时投影，为最近 1–31 日返回历史快照覆盖、缺失日期和已有修正日期数。
- 在固定测试门禁开启时登记方法任务，每日 00:10 为所有活动测试机构幂等生成前一自然日快照。
- 允许上级在原始记录完成补录或更正后，对已结束日期的最新日报追加修正版。
- 保存修正原因、前一版本、来源摘要、指标差异和重点事项变化标志，保证旧版本不可变。
- 增加上级菜单按钮、Casbin 权限、API、前端运营概览和修正对话框。

### 1.2 本任务非范围

- 不新增运营、财务或医疗角色，不新增人员/团队转交归属模型。
- 不实现正式 KPI、排名、绩效、跨机构分析、导出或法定/经营报表。
- 不允许手工输入汇总数字，也不以日报修正替代原始业务事实的更正。
- 不启用真实短信、真实个人数据、医疗内容或任何面向用户的 AI。
- 不新增人工触发初始日报的 HTTP 接口，不在单任务内执行页面点触。
- 不提前实现 P2-05 数据生命周期、P2-06 AI 影子验证或 P2-07 灰度演练。

## 2. 歧义处理与安全决策

需求提到运营看板和历史修正，但没有批准运营岗位、团队转交归属、人员绩效口径或正式报表用途。直接引入这些概念会改变角色、数据模型和合规边界，因此本任务停在以下可审计范围：

- 继续使用现有 `SUPERVISOR`，不创建新角色；
- 只按当前授权机构汇总，不计算团队或个人归属；
- 明确返回 `formalReportingEnabled=false` 和 `attributionPolicyStatus=PENDING_APPROVAL`；
- 自动任务只处理固定测试记录，不能被配置为正式运行能力；
- 后续若批准正式用途，需单独冻结业务日、转交、人员归属、审计与导出契约，并进行独立迁移评审。

## 3. 指标口径

时区固定为 `Asia/Shanghai`，自然日采用半开区间 `[00:00, 次日 00:00)`。今日实时投影的截止点为请求时刻，历史版本的截止点为业务日结束。

| 指标 | `P2-04-v2` 定义 |
| --- | --- |
| `servedClients` | 业务日内存在到期任务的去重服务人数 |
| `dueTasks` | 业务日内到期的任务数 |
| `submittedTasks` | 业务日开始后、统计截止前提交的任务数 |
| `overdueTasks` | 统计截止前已到期且未提交，或提交时间晚于到期时间的任务数 |
| `deliveryIssues` | 统计截止时仍活动的通知异常待办数 |
| `openAttentionCases` | 统计截止时仍未关闭的关注事项数 |
| `resolvedAttentionCases` | 业务日开始后、统计截止前解决的关注事项数 |
| `consultationsOpened` | 业务日开始后、统计截止前新增的咨询数 |
| `consultationsClosed` | 业务日开始后、统计截止前关闭的咨询数 |
| `openConsultations` | 统计截止时仍未关闭的咨询数 |
| `openTodos` | 统计截止时仍活动的统一待办数 |
| `reviewRequired` | 统计截止时处于等待上级复核的关注事项数 |

指标和重点事项只读取当前机构内活动测试客户的事实。前端只展示服务端数值，不在浏览器重算口径。

## 4. 数据模型与迁移

`daily_summary_versions` 保持 `organization_id + business_date + version` 唯一，并增量增加：

| 字段 | 用途 |
| --- | --- |
| `generation_type` | `SCHEDULED|CORRECTION|SYSTEM_RECOMPUTE|LEGACY` |
| `source_cutoff_at` | 本版读取原始记录的统计截止时间 |
| `previous_version_id` | 指向同一业务日期的前一版本 |
| `correction_reason` | 上级提交的事实性修正原因 |
| `source_digest` | 指标和重点事项快照的 SHA-256 摘要，不对外返回 |
| `revision_changes_json` | 相对前一版本发生变化的指标列表 |
| `focus_cases_changed` | 重点事项快照是否变化 |
| `command_*` | 修正命令的操作者、操作、幂等摘要和请求摘要，不返回原始幂等键 |
| 四个咨询/待办指标列 | 保存新增、关闭、未结咨询和活动待办数 |
| `overdue_tasks` | 保存逾期任务数 |

迁移通过现有 GORM AutoMigrate 增加列，不删除或重写 `P1-08-v1` 历史记录。旧记录缺少生成方式时按 `LEGACY` 返回；其原指标仍可读。回退代码不会物理删除新增列或版本，物理清理必须另行审批和备份。

## 5. 状态、版本与幂等

日报状态由类型和版本共同表达：

- 今日：`REALTIME_PREVIEW`，`id=0`、无版本号、不持久化；
- 首个历史版本：通常由 `SCHEDULED` 生成，版本从 `1` 开始；
- 修正版：`CORRECTION`，必须引用前一版本并递增版本号；
- 受控复算：`SYSTEM_RECOMPUTE`，只允许系统身份调用；
- 早期记录：`LEGACY`，保持只读兼容。

修正命令必须同时满足：

1. 调用人是当前机构上级；
2. 目标是已结束业务日的当前最新版本；
3. `expectedVersion` 与目标版本一致；
4. 提供非空 `Idempotency-Key` 和事实性修正原因；
5. 重新读取原始记录后的来源摘要与当前版本不同。

成功后只追加新版本。相同键和相同请求重放原结果；若之后又产生新版本，重放的旧结果返回 `isLatest=false`。相同键和不同请求、旧版本、今日实时项、跨机构目标或无变化复算均拒绝。

## 6. 接口与权限

| 方法 | 路径 | 权限与用途 |
| --- | --- | --- |
| `GET` | `/care/operations-dashboard?days=7` | 上级读取当前机构今日投影及最近窗口覆盖；`days` 为 1–31 |
| `GET` | `/care/daily-summaries` | 上级分页读取今日实时项与历史所有版本 |
| `GET` | `/care/daily-summaries/{id}` | 上级读取授权机构内冻结版本、差异和重点事项 |
| `POST` | `/care/daily-summaries/{id}/revisions` | 上级基于最新版本重新复算并追加修正版 |

员工路由继续使用 `JWT -> MustChangePwdGuard -> Casbin -> DataScope`。Service 层透传 Context 并校验业务角色和机构归属；页面按钮只控制入口可见性，不能替代后端授权。普通管理员、管家、医护、内容管理员、跨机构身份和缺业务身份均失败关闭。

系统生成没有 HTTP 入口。`GenerateScheduledSnapshots` 和兼容复算入口要求系统身份，不能由员工请求上下文调用。

## 7. 自动生成与故障边界

固定测试门禁开启时，初始化幂等登记：

- 任务名：`CareDailySummary`
- 执行方法：`GenerateCareDailySummaries`
- 计划：`CRON_TZ=Asia/Shanghai 10 0 * * *`
- 目标日期：执行时的前一自然日

任务只枚举活动测试机构，并为缺少 `P2-04-v2` 记录的日期创建快照。重复运行返回已有版本，不重复追加。单个机构失败会被汇总记录，其他机构仍继续尝试；Context 取消会立即停止。门禁关闭时不创建任务，并停用已存在的同名任务。

若同名任务已指向其他执行器或方法，初始化失败而不是静默覆盖。已有任务被人工暂停后，重新初始化不会擅自启用。

## 8. 运营看板与前端

运营看板默认覆盖今日加最近六个历史日，最多 31 日。响应包含：

- `current`：今日十二项实时指标；
- `recentSnapshots`：每个历史日期的当前最新版本；
- `coverage.snapshotDays`：已有快照的历史日期数；
- `coverage.missingDates`：缺失日期；
- `coverage.revisedDates`：存在多个版本的日期数；
- 测试用途、正式报表关闭和归属策略待批准标志。

每日汇总页增加覆盖卡片、十二项今日指标、生成方式、版本元数据、修正差异和追加修正对话框。修正对话框只提交原因和当前版本，数字始终由服务端复算。样式使用 UnoCSS 原子类和既有主题变量，没有新增内联样式或 scoped CSS。

# 阶段一 P1-05：移动端受限访问与任务提交

## 交付范围

本任务实现固定演示数据下的客户端受限访问闭环：一次性 grant、HttpOnly 会话、本人任务列表/详情、任务说明确认、问卷填写、草稿恢复、提交确认、成功与失效状态。

不启用真实短信、grant 投递后台、正式认证、面向用户的 AI、医疗内容创作或关注事项创建。D2–D5 继续沿用 P1-04 的开放时间和空问卷绑定。

## 数据模型

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `care_client_accounts` | 客户端独立安全主体 | `care_client_id` 唯一，不复用员工账号 |
| `client_access_grants` | 一次性访问能力 | 只存 token 摘要；任务范围 JSON；兑换/过期/撤销时间 |
| `client_sessions` | HttpOnly 会话 | 只存 token 摘要；`grant_id` 唯一；复制固定任务范围 |
| `client_task_command_receipts` | 客户端写操作重放 | 客户、操作、幂等键摘要联合唯一 |
| `questionnaire_task_drafts` | 任务当前草稿 | `task_id` 唯一；独立版本；提交后保留并标记已消费 |

迁移只增表和索引，不删除、重命名或回填 P1-02 至 P1-04 数据。固定初始化只创建账户，不落库可用 grant。

## 状态和事实

- grant：`ISSUED -> REDEEMED`；撤销与过期不能兑换，外部提示与无效链接一致。
- session：`ACTIVE`，过期或撤销后统一返回 `41103`。
- 任务：系统开放后为 `OPEN`；客户端确认并开始填写后为 `IN_PROGRESS`；提交后为 `SUBMITTED`。
- 事实：`ClientTaskOpened`、`ClientTaskConsented`、`TaskAnswerStarted`、`TaskAnswerSubmitted` 分别写入 `care_path_events`。
- D1 提交后审核状态为 `PENDING`；这不表示已处理。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/care/client-access/redeem` | 原子兑换 grant 并设置 Cookie |
| GET | `/care/client/tasks` | 当前会话的受限任务分页 |
| GET | `/care/client/tasks/{taskId}` | 可进入任务的客户端详情 |
| GET | `/care/client/tasks/{taskId}/questionnaire` | 冻结题目和可空草稿 |
| POST | `/care/client/tasks/{taskId}/interactions` | 打开、确认、开始事实 |
| PUT | `/care/client/tasks/{taskId}/draft` | 保存部分答案草稿 |
| POST | `/care/client/tasks/{taskId}/submit` | 原子提交并更新任务 |

客户端请求和响应以 `docs/contracts/sleep-care-phase1.openapi.yaml` 为准，Swagger 注释使用具体请求/响应类型。

## 权限与隐私

- grant/session 原文不进入数据库、响应、Swagger 或访问日志。
- 移动端不发送员工 token，不加载员工动态菜单。
- 服务端从 session 推导客户和任务白名单，路径参数不能扩大范围。
- session 写请求必须匹配配置的精确 `Origin`。
- 客户端 DTO 不下发身份、组织、计划内部标识、规则条件、审核记录和内部环境标志。
- 浏览器读取 grant 后立即替换历史地址；表单本地进度在提交成功后清除。

## 提交事务与幂等

提交协调器先锁定任务。若已有提交，规范化答案一致则返回原提交，不一致则返回幂等冲突；新提交在一个事务中复用 questionnaire 服务，随后更新任务、记录提交事实并消费草稿。任一步失败，答卷、outbox、任务状态和事件全部回滚。

P1-05 的提交协调器已在 P1-06 扩展：规则未命中时 `attentionCaseIds` 为空；命中时在同一外层事务中去重创建关注事项、活动待办和 outbox 事实，并返回事项 ID。缺少有效责任管家时答卷与事项相关写入全部回滚。

## 移动端恢复

移动页面位于同一 Vite 工程的 `/client/**` 静态路由，使用独立布局。填写时本地保存答案并延迟同步服务端草稿；网络失败保留本地副本，恢复联网后重试。提交幂等键在成功前复用，防止双击或网络重试产生第二份答卷。

## 本任务验证

- clientaccess 服务：兑换、过期/已用链接、session 范围、交互顺序、草稿、等价重复提交、不同内容冲突、事务回滚，专项 Go 测试通过。
- 日志与来源：grant、answers、Cookie 和 token 脱敏测试、精确 Origin 正负测试通过。
- 初始化：固定账户重复初始化测试通过，并确认不创建 grant 或 session。
- 契约：OpenAPI YAML 解析及本地引用检查通过，`make swagger-check` 通过。
- 前端：相关 ESLint 和 `npm run build` 通过。
- 按阶段规则不执行页面点触；常见手机尺寸交互留到阶段集中验收。

> 日期：2026-08-18

## 1. 交付结论

P1-02 已实现一份跨路径复用的 `CareClient` 公共资料、追加式授权/撤回事实、有有效期的管家/医护责任关系，以及 GVA DataScope 与业务责任关系叠加的 fail-closed 权限策略。

本任务提供：

- 康养用户列表、详情、新建固定演示用户、维护公开资料；
- 管家/医护责任关系的创建、排期和显式转交；
- 合成测试参与授权的授予与撤回记录；
- 合成机构、团队、角色、员工、用户和责任关系夹具；
- GVA 菜单、按钮、API、Casbin、DataScope 与业务责任关系配置；
- 最小后台页面、Swagger 契约、专项测试和容器运行验收。

## 2. 范围与非范围

### 2.1 本任务范围

- `CareClient` 只保存公共服务资料，不保存路径任务、问卷答案、规则命中或医疗判断。
- `CareAssignment` 分别表达 `CARE_STEWARD` 和 `CLINICIAN` 责任，并保留开始、结束、替代关系和原因。
- `ConsentRecord` 以追加事实表达合成测试授权与撤回，不覆盖历史。
- `SysDepartment` 继续作为组织树；扩展表只标识康养机构/团队业务元数据，不另建平行组织树。
- `SysAuthority` 继续作为后台角色；扩展表把可变的 GVA 角色 ID 映射为稳定领域角色。
- 管家/医护查询必须同时满足 GVA DataScope 和当前有效责任关系；上级医师按组织树范围查看。
- 缺少身份、缺少领域角色、普通管理员或越权组织访问时服务端拒绝。

### 2.2 本任务非范围

- 不实现康养用户移动端账号、一次性 grant 或受限会话；它属于 P1-05。
- 不实现问卷、答卷、规则版本或医疗内容；它属于 P1-03。
- 不实现 OSA 计划、D1–D5 任务、关注事项、工作台、督导和通知；它们属于 P1-04 至 P1-09。
- 不完成阶段一全部角色的终局菜单和权限矩阵；本任务只配置康养用户页，P1-10 继续完成全链权限验收。
- 不接入真实机构、真实用户、真实授权文本、短信供应商或 AI。

## 3. 数据模型与迁移

本任务使用 GORM `AutoMigrate` 新增六张业务表：

| 表 | 聚合/用途 | 关键约束 |
| --- | --- | --- |
| `care_clients` | 唯一公共资料 | `display_code` 唯一；机构/团队归属；`synthetic`；乐观锁 `version`；`dept_id` |
| `care_assignments` | 责任历史 | 用户、机构、团队、责任人、角色、有效期、替代关系；追加保存，不覆盖旧责任 |
| `care_consent_records` | 授权事实 | 授权类型、授予/撤回、文本版本、发生时间、来源、记录人；追加保存 |
| `care_org_unit_profiles` | 组织扩展 | `department_id` 唯一；区分 `ORGANIZATION`/`TEAM`；复用 `sys_departments` |
| `care_authority_profiles` | 领域角色映射 | `authority_id` 唯一；映射管家、医护、上级医师 |
| `care_client_command_receipts` | 写命令幂等 | 操作人 + 操作 + `Idempotency-Key` 唯一；保存请求摘要和首次结果 |

迁移随服务启动执行。未引入 P1-03 以后的表，也没有删除或改写上游 GVA 表。

## 4. 状态与不变量

### 4.1 康养用户

- 状态：`ACTIVE`、`INACTIVE`。
- P1-02 新建接口仍只接受 `synthetic=true`，该字段是服务端安全门禁，不作为展示命名规则。
- 编码与名称使用普通业务值；只要求非空，不要求固定前缀、括号标签或特定子串。
- 创建后公共资料通过 `expectedVersion` 乐观锁更新。
- 存在当前有效责任关系时不能直接改变团队，必须先走责任转交语义。

### 4.2 责任关系

- 计算状态：`SCHEDULED`、`ACTIVE`、`ENDED`、`CANCELLED`。
- 责任类型：`CARE_STEWARD`、`CLINICIAN`。
- 同一康养用户、同一责任类型的时间区间不能重叠。
- 转交必须显式传入 `replacesAssignmentId`；旧记录写入结束事实，新记录引用旧记录。
- 新责任人必须启用、属于康养用户当前团队且领域角色与责任类型一致；P1-02 不提供跨团队隐式转交。

### 4.3 授权事实

- P1-02 只允许 `SYNTHETIC_TEST_PARTICIPATION`。
- 动作：`GRANT`、`WITHDRAW`；来源固定为 `STAFF_RECORDED`。
- 没有有效授权时不能撤回；已授权时不能重复授予。
- 当前状态由最新事实计算为 `PENDING`、`GRANTED` 或 `WITHDRAWN`。
- 该记录只用于合成测试，不代表真实个人授权或正式服务协议。

### 4.4 幂等与并发

- 所有写接口必须携带 `Idempotency-Key`，长度不超过 128。
- 同操作人、同操作、同键、同请求返回首次结果。
- 同键不同请求返回 `41002 IDEMPOTENCY_CONFLICT`。
- 聚合版本过期返回 `41003 VERSION_CONFLICT`，不产生部分历史。

## 5. 接口

所有接口复用 GVA 私有路由、JWT、Casbin 和统一 `{code,data,msg}` 响应。

| 方法 | 路径 | 权限与用途 |
| --- | --- | --- |
| `GET` | `/care/clients` | 管家/医护按有效责任关系，上级按组织范围分页查询 |
| `GET` | `/care/clients/{id}` | 在相同范围内读取公共资料、责任历史和合成授权历史 |
| `GET` | `/care/client-options` | 仅上级读取可管理机构、团队和可选责任人 |
| `POST` | `/care/clients` | 仅上级创建固定演示用户；请求仍须携带内部安全标志 |
| `PUT` | `/care/clients/{id}` | 仅上级用乐观锁维护公开资料 |
| `POST` | `/care/clients/{id}/assignments` | 仅上级追加或转交责任关系 |
| `POST` | `/care/clients/{id}/consent-records` | 仅上级追加合成测试授权/撤回事实 |

分页最大 `pageSize=100`。字段和错误码的机器可读契约见 [sleep-care-phase1.openapi.yaml](./contracts/sleep-care-phase1.openapi.yaml)；当前运行接口也已生成到 `server/docs/`。

## 6. 权限与数据隔离

权限判断按下列顺序叠加，任何一层失败都不能由下一层放宽：

```text
JWT 员工身份
  → GVA 菜单与按钮
  → Casbin path + method
  → GVA DataScope 机构/团队范围
  → CareAuthorityProfile 领域角色
  → CareAssignment 当前有效责任关系
```

角色策略：

| 角色 | 列表/详情 | 写操作 | 联系方式 |
| --- | --- | --- | --- |
| 合成健康管家 | 仅本人当前负责的用户 | 禁止 | 基础级脱敏，只保留末四位 |
| 合成一线医护 | 仅本人当前负责的用户 | 禁止 | 允许敏感级显示 |
| 合成上级医师 | 仅所属机构及下级团队 | 允许 P1-02 写操作 | 允许敏感级显示 |
| 普通 GVA 管理员 `888` | 默认拒绝 | 默认拒绝 | 不返回业务数据 |
| 缺身份/未映射角色 | 拒绝 | 拒绝 | 不返回业务数据 |

菜单和前端按钮只改善界面体验，服务端 Casbin、DataScope 和 `internal/accesspolicy` 才是安全边界。

## 7. 合成夹具

Compose 本地环境显式启用夹具，非显式配置环境默认关闭。夹具固定包含：

- 两个醒目标注的合成机构及各自团队；
- 健康管家、一线医护、上级医师三个合成角色；
- 机构 A 两名管家、一名医护、一名上级医师，机构 B 一名管家；
- 机构 A 两名康养用户、机构 B 一名康养用户；编码与名称采用自然业务值；
- 四条责任关系和一条合成测试授权事实。

夹具密码由 `make init` 写入本机 `.env`，不会写入 Git。只在本机执行 `make credentials` 查看账号和当前密码，禁止把输出粘贴到文档、日志、截图或提交中。

## 8. 前端页面

动态菜单组件为 `view/sleep-care/clients/index.vue`，组件名固定为 `CareClients`。页面提供：

- 页面级演示环境提示、筛选、分页和空/错/loading 状态；记录编码和名称不追加环境标签；
- 公共资料与当前责任摘要；
- 详情抽屉中的完整责任和合成授权时间线；
- 上级医师可见的新建、维护、责任记录和授权记录弹窗；
- 管家/医护只读按钮权限。

页面只通过 `web/src/api/sleep-care/care-clients.js` 调用统一请求封装，不在页面中自行判断可见数据范围。

# 阶段一 P1-10 完整权限、菜单与数据隔离

## 范围

- 为管家、医护、上级和内容管理员收敛完整动态菜单。
- 以显式白名单统一菜单、按钮、Casbin、DataScope 和责任关系五层权限。
- 增加内容管理员固定测试角色与账号，只读问卷和 OSA 方案定义。
- 增加用户、任务、关注事项、个案复核四个隐藏详情路由及 `activeName`。
- 将默认首页设为角色已获授权的可见叶子。
- 对四角色、系统管理角色、缺身份、跨机构和无责任关系场景补齐正向/负向测试。

## 非范围

- 不新增或修改 HTTP 请求/响应结构。
- 不提供问卷或方案编辑、发布、审批能力。
- 不改变移动端受限会话、提交事务或任何业务生命周期。
- 不接真实短信，不启用面向用户的 AI，不增加医疗题目、阈值、判断或建议。
- 本任务不做页面点触、Compose 全量重建或阶段一端到端验收；这些归 P1-11。

## 数据模型

本任务没有新增业务表或字段，复用：

- `sys_authorities`：角色、DataScope 和默认首页；
- `sys_base_menus`：动态菜单、隐藏路由、组件和 `activeName`；
- `sys_base_menu_btns` / `sys_authority_btns`：按钮 key 及角色关联；
- `sys_authority_menus`：角色菜单关联；
- `casbin_rule`：路径和 HTTP 方法授权；
- `care_authority_profiles`：可变系统角色到稳定领域角色的映射；
- 现有用户、部门和关联表：固定测试账号的组织归属。

新增稳定领域角色 `CONTENT_ADMIN`，固定角色 ID 为 `9804`、账号记录 ID 为 `9205`。它使用既有 profile 表，不扩展客户或运行态数据模型。

## 状态

本任务不新增业务状态。权限判定只有“允许 / 拒绝”，并保持失败关闭：

```text
员工身份
  -> 动态路由/按钮可见性
  -> Casbin(path + method)
  -> DataScope(部门范围)
  -> 领域角色
  -> 当前责任关系
  -> 允许
```

任一服务端层缺失或拒绝，业务请求即失败。前端隐藏与 `activeName` 只用于导航，不参与最终安全判定。

默认首页：

| 角色 | 默认首页 | 验证条件 |
| --- | --- | --- |
| 管家 | `CareWorkbench` | 已授权、可见、无可见子菜单 |
| 医护 | `CareWorkbench` | 已授权、可见、无可见子菜单 |
| 上级 | `CareDailySummaries` | 已授权、可见、无可见子菜单 |
| 内容管理员 | `CareQuestionnaires` | 已授权、可见、无可见子菜单 |

| 能力 | 管家 | 医护 | 上级 | 内容管理员 |
| --- | --- | --- | --- | --- |
| 问卷版本只读 | 拒绝 | 允许 | 允许 | 允许 |
| 服务计划只读 | 允许 | 允许 | 允许 | 允许 |
| 客户与责任范围读取 | 当前责任 | 当前责任 | 部门树 | 拒绝 |
| 计划运行态与任务读取 | 当前责任 | 当前责任 | 部门树 | 拒绝 |
| 计划启动/暂停/恢复 | 当前责任 | 当前责任 | 拒绝 | 拒绝 |
| 关注事项读取 | 当前责任 | 当前责任 | 部门树 | 拒绝 |
| 通知状态读取 | 当前责任 | 当前责任 | 部门树 | 拒绝 |
| 督导与复核 | 拒绝 | 拒绝 | 允许 | 拒绝 |

员工后台壳层只保留取菜单、取用户信息和退出所需的三条最小策略。系统管理角色 `888` 不获得 `/care/**` 权限。

## 菜单与隐藏路由

```text
睡眠康养随访
├── 工作台
├── 康养用户
├── 执行管理
│   ├── 今日任务
│   ├── 关注事项
│   └── 通知状态
├── 内容管理
│   ├── 问卷内容
│   └── 服务计划
└── 督导中心
    ├── 每日汇总
    └── 待复核事项
```

隐藏路由：

| 路由名 | 组件 | `activeName` | 授权角色 |
| --- | --- | --- | --- |
| `CareClientDetail` | `clients/detail.vue` | `CareClients` | 管家、医护、上级 |
| `CareTaskDetail` | `tasks/detail.vue` | `CareTasks` | 管家、医护、上级 |
| `CareAttentionCaseDetail` | `attention-cases/detail.vue` | `CareAttentionCases` | 管家、医护、上级 |
| `CareReviewDetail` | `review-queue/detail.vue` | `CareReviewQueue` | 上级 |

每个 wrapper 都有唯一组件名，从路由参数打开现有详情抽屉。对应角色同时获得该隐藏路由需要的按钮 key；未获得路由的角色即使手工输入地址，也不能绕过后端接口授权。

## 权限

### 菜单和按钮

- 管家：工作台、客户、执行、服务计划；可启动/暂停/恢复计划，记录任务联系，确认/联系事项，并在联系提交后自动转交责任医护，补发终态异常通知。
- 医护：工作台、客户、执行、问卷与服务计划；可启动/暂停/恢复计划，记录任务联系，确认/处置/关闭事项。
- 上级：工作台、客户、执行、内容、督导；可维护客户公共资料与责任关系，关闭/重开事项，查看日报并指导或介入复核。
- 内容管理员：只有问卷和方案预览按钮。

按钮只控制交互入口。写操作仍要求业务角色、资源范围、责任关系、版本和幂等条件。

### DataScope 和责任关系

- 管家、医护使用部门范围，并在客户、计划、任务、事项、通知查询上叠加当前有效责任关系。
- 上级使用本部门及子部门范围；跨组织记录被 DataScope 拒绝。
- 内容管理员使用最小 DataScope，但内容定义是全局无归属表；独立内容决策只允许读取定义。
- `ResolvePlanContent` 与 `ResolveCareClient` 分离，保证内容只读不会扩展为运行态访问。
- 缺身份、系统身份、未映射角色和系统管理角色全部失败关闭。

## 迁移与初始化

- 无结构迁移。
- `phase_one_access_control.go` 在所有阶段一模块初始化完成后运行。
- 菜单树和隐藏路由元数据始终幂等维护。
- 固定测试开关关闭时，不创建角色/账号或授权关联。
- 开关开启时，对四个固定角色先清除旧菜单、按钮和 Casbin `p` 策略，再写入当前白名单。
- 对系统管理角色额外删除阶段一业务菜单、按钮和 `/care/**` 策略，避免配置权限被误当成数据权限。

## 关键测试与证据

- 初始化连续执行两次，菜单、按钮、角色关联和 Casbin 数量不变。
- 对阶段一菜单全集逐角色验证允许/拒绝；隐藏路由的层级、隐藏标志和 `activeName` 精确匹配。
- 对所有按钮逐角色验证允许/拒绝；预置的陈旧按钮授权会被清除。
- 对阶段一 API 并集逐角色验证路径与方法；预置的越权和非业务策略会被清除。
- 四个默认首页均验证已授权、可见且为叶子。
- 登录回归验证旧账号地址不会覆盖新账号默认首页，且上一账号页签与动态路由不会残留。
- 内容管理员可读取问卷/方案定义，但 `ResolveCareClient`、客户计划和任务服务均拒绝。
- 既有服务测试继续覆盖同部门无责任关系、跨机构、普通管理员和缺身份拒绝。
- 定向 Go 测试覆盖 initializer、access policy 及七个业务 service 包；前端 ESLint 和生产构建通过。
- 本任务无 API 契约变化；Swagger 只做一致性检查，不增加路径或 schema。
- 页面点触按阶段规则留到 P1-11。

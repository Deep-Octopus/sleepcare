# 阶段二 P2-03 通知供应商契约与发送边界

> 执行日期：2026-08-19
>
> 覆盖需求：供应商中立 adapter 契约、请求签名、回调验签、标准回执、重试、限流和费用边界
>
> 数据边界：仅使用固定测试记录，不包含真实个人数据、通知正文或医疗内容
>
> 任务结果：测试契约与安全门禁完成；网络发送、正式短信和用户侧 AI 保持关闭

## 1. 范围与非范围

### 1.1 本任务范围

- 在现有 `NotificationPort` 后增加供应商能力描述，冻结供应商、策略版本、模板、重试、限流和费用边界。
- 提供只面向测试契约的 `ProviderContractAdapter`，对最小请求载荷执行 HMAC-SHA256 签名。
- 接收经过签名验证的标准回调，校验时间窗、nonce、防重放、字段白名单、状态顺序和失败码。
- 每次供应商尝试在同一数据库事务中预留速率和费用额度，并把策略快照写入 attempt。
- 沿用人工补发入口，但限制每个通知请求的最大尝试次数；命令重放不会重复调用 adapter 或重复扣减额度。
- 为管家、医护和上级提供只读门禁接口及前端卡片，明确展示未关闭项和当前边界。
- 扩展日志脱敏与请求体上限，避免回调凭据和外部事件标识进入访问日志。

### 1.2 本任务非范围

- 不选择或接入具体短信供应商，不引入供应商 SDK、域名、账号、真实签名或模板。
- 不实现网络 gateway，不传递手机号、通知正文、诊疗信息或其他个人数据。
- 不启用真实短信、自动重试任务、跨通道降级或任何面向用户的 AI。
- 不把测试参数解释为生产 SLA、价格、资质、模板或回执语义的批准结果。
- 不提前实现 P2-04 运营看板、P2-05 数据生命周期、P2-06 AI 影子验证或 P2-07 灰度演练。

## 2. 决策与启用门禁

需求没有给出正式供应商、资质证据、模板、签名、回执语义、价格或运行保障，且当前明确禁止真实短信。因此本任务把可安全冻结的部分实现为供应商中立契约，不推定任何外部平台。

出厂配置固定为 `DISABLED`，供应商、策略、模板和密钥为空，复核项均为 `false`，重试、限流和费用额度均未设置。`CONTRACT_TEST` 只允许在本地固定记录门禁开启时使用；即使所有测试门禁满足，readiness 仍返回：

- `usageScope = TEST_ONLY`
- `networkDeliveryEnabled = false`
- `formalDeliveryEnabled = false`

正式接入必须另行确认供应商及其公开契约，再新增独立网络实现、密钥托管与运行验证，不能通过修改当前配置直接获得生产发送能力。

## 3. 数据模型与不变量

| 表 / 模型 | 职责 | 关键约束 |
| --- | --- | --- |
| `notification_attempts` | 保存每次发送尝试及冻结策略 | 增加 provider、策略、模板、费用快照；供应商消息 ID 只保存 SHA-256 摘要 |
| `notification_dispatch_reservations` | 保存一次 attempt 的额度预留 | `notification_attempt_id` 唯一；冻结 provider、策略、模板、速率桶、费用桶和金额 |
| `notification_quota_buckets` | 持久化速率窗口与日费用用量 | provider + 策略版本 + 类型 + 窗口键唯一；额度快照不可原地漂移 |
| `notification_provider_callbacks` | 保存已验签回调证据 | provider + event 摘要唯一，provider + nonce 摘要唯一；不保存原始载荷、事件 ID、消息 ID、签名或 nonce |

attempt、额度预留和业务事件共用一个事务。速率额度预留成功但费用校验失败时，整个事务回滚，不留下部分扣减。失败的 gateway 调用不会伪造 `SUBMITTED_TO_PROVIDER` 或 `ACCEPTED` 事实。

## 4. 状态、重试与幂等

通知 attempt 状态机保持：

`PENDING → SUBMITTED_TO_PROVIDER → ACCEPTED → DELIVERED | FAILED | UNKNOWN`

- adapter 只有取得有效受理结果后才追加 `SUBMITTED_TO_PROVIDER` 和 `ACCEPTED`。
- 回调只允许标准状态和既有状态机路径；受理时间不得早于提交时间，终态不得早于受理时间。
- `DELIVERED`、`FAILED`、`UNKNOWN` 为终态，不允许被后续回调覆盖。
- 额度预留状态为 `RESERVED → SUBMITTED → FINALIZED`；终态回执同步完成额度记录。
- 补发仍是人工命令，只能从失败或未知终态创建新 attempt；`attemptNo` 不得超过策略的 `maxAttemptsPerRequest`。
- 相同幂等键和相同请求返回当前事实，不再次调用 adapter；不同请求内容复用同一键继续返回幂等冲突。

## 5. Adapter 与签名契约

`ProviderGateway` 只定义 `Submit(context.Context, SignedProviderSubmission)` port，本任务没有网络实现。发送载荷只包含：

- 通知请求内部引用的摘要；
- attempt 内部引用的摘要；
- 已冻结的模板代码；
- 请求时间。

载荷不包含手机号、目标地址、通知正文、用户姓名或医疗信息。请求与回调采用相同的规范化签名输入：

`unixTimestamp + "\n" + nonce + "\n" + exactRawBody`

签名算法为 HMAC-SHA256，结果使用小写十六进制。密钥至少 32 字节，只能来自运行配置，不进入 readiness、Swagger、数据库、日志或提交文件。

## 6. 回调安全边界

公开回调为 `POST /care/notification-provider-callbacks/{providerCode}`，不使用员工 JWT，而是执行以下独立校验：

1. readiness 所有测试门禁已关闭，且路径 provider 与当前配置一致；
2. 请求体不超过 64 KiB；该限制位于访问日志之前；
3. `X-Notification-Timestamp` 在配置时间窗内；
4. `X-Notification-Nonce` 长度和字符集合法，摘要未被使用；
5. `X-Notification-Signature` 与原始请求体常量时间比较一致；
6. JSON 拒绝未知字段和尾随对象；状态、时间、失败码符合标准契约；
7. provider 消息 ID 摘要能命中同一 provider、同一策略版本的 attempt；
8. 通过以上校验后才使用系统上下文写入回调和 delivery event。

事件 ID、消息 ID、签名和 nonce 在访问日志中被遮蔽。相同事件、相同载荷和相同 nonce 的顺序重放返回当前事实；事件内容冲突或 nonce 被另一事件复用时拒绝。

## 7. 接口与权限

| 方法 | 路径 | 鉴权与用途 |
| --- | --- | --- |
| `GET` | `/care/notification-provider-readiness` | 员工 JWT + Casbin + DataScope；管家、医护、上级只读门禁和边界 |
| `POST` | `/care/notification-provider-callbacks/{providerCode}` | 无员工 JWT；仅接受完整 HMAC 验证通过的供应商标准回调 |
| `POST` | `/care/deliveries/{id}/resend` | 沿用健康管家权限、责任关系、版本和幂等校验，并增加最大尝试次数限制 |

readiness 不返回密钥、原始外部标识或隐藏配置。内容管理员、普通管理员、缺业务身份的账号仍不能读取；页面按钮不是后端授权依据。

## 8. 迁移、初始化与回退

- `bizModel()` 通过 AutoMigrate 增量登记额度预留、额度桶和回调证据三张表，并为 attempt 增加可空或安全默认字段。
- 初始化增加 readiness API 元数据及管家、医护、上级的只读权限，不为公开回调创建员工 Casbin 权限。
- 两份出厂配置均保持 `DISABLED`、空密钥、空供应商和关闭复核项，并由配置契约测试锁定。
- 回退代码提交不会自动删除 attempt 快照、额度记录、回调证据或 delivery event；物理删除需单独审批与备份。

## 9. 前端交付

- 通知记录页增加“供应商启用门禁”卡片，展示测试范围、网络/正式发送关闭状态、未关闭项和重试/限流/费用边界。
- attempt 详情增加 provider、策略版本、模板和预估费用快照，便于核对每次尝试采用的冻结契约。
- 页面继续明确不发送真实短信，不提供密钥编辑、正式启用或外部供应商配置入口。
- 样式使用 UnoCSS 原子类和现有主题 token，没有新增 scoped CSS 或内联样式。

## 11. 未决输入

- 正式供应商、主体资质、消息类型、模板和签名审批材料尚未提供。
- 正式 API 地址、认证方式、请求字段、回执状态映射、重放规则、错误码和可用性承诺尚未确认。
- 正式重试退避、发送时段、速率额度、费用预算、告警阈值、退款/计费语义和备用流程尚未批准。
- 密钥托管、轮换、历史密钥验证、网络出口、监控、对账和故障演练需在具体供应商确定后单独设计与验收。
- 上述输入没有关闭前，当前契约只能用于固定测试记录，不能启用网络或正式发送。

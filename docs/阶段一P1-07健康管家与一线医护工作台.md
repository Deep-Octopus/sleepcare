# 阶段一 P1-07 健康管家与一线医护工作台

## 范围

- 提供按当前角色、部门数据范围和有效责任关系实时聚合的员工工作台。
- 展示今日应随访、等待用户完成、通知异常、问卷关注、待本人处理和待专业复核六项计数。
- 提供关注事项列表、详情、规则命中快照和追加式行动时间线。
- 为管家提供确认、记录联系和升级入口，为医护提供确认、处置、请求上级复核、升级和关闭入口。
- 登记工作台、执行管理和关注事项菜单，以及分角色按钮与 API 权限。

## 非范围

- 不新增上级指导、要求讨论、直接介入和日报；这些由 P1-08 实现。
- 不产生通知尝试、失败待办或补发事实；这些由 P1-09 实现。
- 不扩展全角色默认首页、隐藏详情路由和完整隔离矩阵；这些由 P1-10 集中收口。
- 不展示原始答卷，不从答案生成医疗结论，不启用真实短信或面向用户的 AI。
- 按阶段规则不执行页面点触。

## 数据模型

P1-07 不新增业务表、字段或索引。后端新增非持久化 `WorkbenchData` 响应模型：

| 字段 | 含义 |
| --- | --- |
| `dueToday` | `Asia/Shanghai` 当日到期且未提交/取消的任务 |
| `waitingClient` | 已开放或正在填写的用户任务 |
| `deliveryIssues` | 尚未完成的 `DELIVERY_ISSUE` 统一待办 |
| `attentionCases` | 尚未关闭的关注事项 |
| `assignedToMe` | 当前分配给请求人的开放待办 |
| `reviewRequired` | `reviewStatus=PENDING` 的计划任务 |

计数完全由既有 `TaskInstance`、`AttentionCase`、`TodoItem`、`CareClient` 与责任关系实时投影。

## 状态

- 工作台不引入新状态机，也不把实时计数保存为日报。
- 管家联系与医护处置沿用 P1-06 关注事项状态机。
- 医护请求上级复核时，处置记录写入 `WAITING_SUPERVISOR`；当前活动待办不会被完成或替换。

## 接口

| 方法 | 路径 | P1-07 用途 |
| --- | --- | --- |
| GET | `/care/workbench` | 返回六项实时计数 |
| GET | `/care/attention-cases` | 事项队列 |
| GET | `/care/attention-cases/{id}` | 事项详情、命中快照和时间线 |
| POST | `/care/attention-cases/{id}/acknowledge` | 确认事项 |
| POST | `/care/attention-cases/{id}/handling-records` | 记录联系、处置或请求复核 |
| POST | `/care/attention-cases/{id}/escalate` | 升级至有效责任医护 |
| POST | `/care/attention-cases/{id}/close` | 关闭已解决事项 |
| POST | `/care/attention-cases/{id}/reopen` | 授权上级重开事项 |

前端封装位于 `web/src/api/sleep-care/case-work.js`；写操作继续要求 `Idempotency-Key` 和 `expectedVersion`。

## 权限

| 能力 | 管家 | 医护 | 上级 |
| --- | --- | --- | --- |
| 工作台/事项读取 | 允许 | 允许 | 管理部门范围 |
| 确认 | 允许 | 允许 | 不允许 |
| 记录联系 | 允许 | 不允许 | 不允许 |
| 记录处置/请求复核 | 不允许 | 允许 | 不允许 |
| 升级 | 允许 | 允许 | 不允许 |
| 关闭 | 不允许 | 允许 | 允许 |
| 重开 | 不允许 | 不允许 | 允许 |

菜单和按钮只负责界面入口；安全边界由 `JWT -> MustChangePwdGuard -> Casbin -> DataScope` 以及 Service 层的责任关系、当前责任人与角色校验共同实现。

## 迁移与初始化

- 无 GORM 业务模型迁移。
- 初始化幂等登记 `/care/workbench` API、菜单层级、按钮 key、角色菜单关系与 Casbin 策略。
- 既有计划任务菜单移入“执行管理”；重复启动会收敛到同一层级和权限关系。

## 关键测试与证据

- 验证管家不能写专业处置，医护请求复核后事项进入 `WAITING_SUPERVISOR` 且活动待办仍开放。
- 验证菜单层级、按钮角色矩阵、Casbin 路径和路由注册。

- `make swagger-check`：通过；阶段一 OpenAPI YAML 可解析，工作台字段与实现一致。

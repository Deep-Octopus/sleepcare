## 1. 交付结论

P1-04 已实现普通 `carePath` 模块，包含不可变 OSA 合成路径/计划模板版本、路径加入记录、启动前预览、幂等计划启动、D1–D5 任务实例、三个独立任务状态轴、`KEEP_WINDOWS` 暂停/恢复、责任范围查询、审计事件和共享事务型 outbox。

本任务固定启用一份 `TEST_ONLY` 合成定义：D1 冻结问卷版本 `9401` 和规则版本 `9501`；D2–D5 不绑定问卷或规则。所有任务执行角色均为 `CARE_CLIENT`，通知策略均为 `DISABLED`。这些内容只验证软件行为，不构成医疗路径、诊疗建议或真实服务安排。

## 2. 范围与非范围

### 2.1 本任务范围

- 版本化路径、计划模板、任务定义和可选依赖数据结构。
- 明确的 `anchorAt`；D1–D5 绝对开放/截止时间由冻结相对秒数计算。
- 30 分钟有效的持久化预览；确认启动后消费预览。
- 启动、暂停、恢复命令的 `Idempotency-Key`、请求哈希和首次结果回放。
- 康养用户乐观锁与计划乐观锁；同一用户同一路径仅一个活动加入记录。
- `executionStatus`、`timingStatus`、`reviewStatus` 三轴分离。
- 固定时钟下的任务开放协调；暂停期间不开放新任务，恢复时补开已到开放点的任务，但不平移窗口。
- `CarePlanStarted`、`CarePlanPaused`、`CarePlanResumed`、`TaskOpened` 审计事实和 outbox。
- 计划模板只读页、责任范围任务只读页、康养用户详情中的计划时间线与启动/暂停/恢复入口。

### 2.2 本任务非范围

- 不提供康养用户移动端、受限会话、填写、草稿或提交；它们属于 P1-05。
- 不创建关注事项、处置、上级指导、工作台、日报或通知异常待办。
- 不启用跳过、取消、补填、重排、计划终止或模板升级动作；仅保留未来模型常量/数据结构边界。
- 不接入独立常驻调度 worker；本任务提供可注入时钟和幂等 `ReconcilePlanTasks` 协调缝，启动与恢复会执行相应协调。
- 不发送短信、站内通知或外部消息；通知策略固定禁用。
- 不提供正式 OSA 任务内容、临床阈值、医疗结论、诊断或用户侧 AI。
- 不创建正式内容写入口；定义仅由严格合成种子提供。

## 3. 数据模型与迁移

迁移沿用启动期增量 GORM `AutoMigrate`，新增十张表并复用 P1-03 的 `outbox_events`：

| 表 | 用途 | 关键约束 |
| --- | --- | --- |
| `care_path_definition_versions` | 不可变路径版本 | 编码 + 版本唯一；生命周期、范围、审核、定义哈希 |
| `care_plan_template_versions` | 不可变计划模板版本 | 编码 + 版本唯一；路径版本、锚点、逾期与暂停策略 |
| `care_plan_task_definitions` | D1–D5 冻结任务定义 | 模板 + 日序唯一；相对窗口、角色、问卷/规则、通知策略 |
| `care_plan_task_dependencies` | 显式任务依赖 | 任务 + 前置任务唯一；P1-04 合成模板固定为 0 条 |
| `care_path_enrollments` | 用户路径加入记录 | 用户 + 路径 + 活动槽唯一；活动槽防止重复启动 |
| `care_plan_previews` | 启动前预览 | opaque `preview_id` 唯一；模板哈希、过期和消费事实 |
| `care_plan_instances` | 计划实例 | 加入记录和预览唯一；锚点、状态、暂停策略、乐观锁版本 |
| `care_task_instances` | 冻结任务实例 | 计划 + 任务定义唯一；三轴状态、绝对窗口和内容绑定 |
| `care_path_events` | 计划/任务审计事实 | 事件 ID 唯一；操作者、来源、前后状态、原因和发生时间 |
| `care_path_command_receipts` | 写命令幂等回执 | 操作人 + 操作 + 幂等键唯一；请求哈希与首次结果 |
| `outbox_events`（复用） | 事务型领域事件 | 事件 ID 唯一；聚合、载荷、关联/因果标识和合成标记 |

定义表是全局不可变配置，不带行级归属字段；运行表使用标准 `dept_id`、`created_by`、`updated_by`，由统一 DataScope 回调过滤和盖章。Service 只透传请求上下文，不接受客户端字段决定机构或责任范围。

迁移只新增表/索引并复用既有 outbox，不删除、不重命名、不清空上游数据。常规回滚应先回退代码并保留数据；任何删表或清卷操作都必须另行获得明确授权。

## 4. 状态、时间与不变量

### 4.1 路径加入与计划状态

模型保留 `DRAFT`、`PENDING_START`、`ACTIVE`、`PAUSED`、`COMPLETED`、`TERMINATED`。P1-04 写入口只允许：

```text
ACTIVE --填写原因/expectedVersion--> PAUSED
PAUSED --填写原因/expectedVersion--> ACTIVE
```

- 暂停策略固定为 `KEEP_WINDOWS`；暂停和恢复不修改任何任务的 `openAt`、`dueAt`。
- 暂停期间协调器不开放新任务；恢复后按原窗口开放已到点的 `SCHEDULED` 任务。
- P1-04 不暴露完成、终止、取消、跳过、补填或重排动作。

### 4.2 任务三个状态轴

| 状态轴 | P1-04 值与语义 |
| --- | --- |
| 执行 `executionStatus` | `SCHEDULED`、`OPEN`；同时保留后续 `IN_PROGRESS`、`SUBMITTED`、`CANCELLED` 常量，但本任务无对应写入口 |
| 时效 `timingStatus` | `NOT_OPEN`、`WITHIN_WINDOW`、`OVERDUE`、`EXPIRED`；由注入时钟和窗口即时推导 |
| 复核 `reviewStatus` | D1 初始 `NOT_READY`，D2–D5 为 `NOT_REQUIRED`；本任务不执行复核动作 |

`DENY` 逾期策略下，到达 `dueAt` 即推导为 `EXPIRED`，但不会覆盖执行状态或删除任务。通知失败能力尚未启用，因此也不存在通知结果删除后续任务的路径。

## 5. 接口

所有接口位于 GVA 私有路由，复用 JWT、MustChangePwdGuard、Casbin、DataScope 和统一 `{code,data,msg}` 响应：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/care/plan-versions` | 分页查询受控合成计划模板版本 |
| `GET` | `/care/plan-versions/{id}` | 查询模板审核、门禁、哈希和 D1–D5 定义 |
| `POST` | `/care/clients/{id}/plan-previews` | 按明确模板版本和 `anchorAt` 幂等生成预览 |
| `POST` | `/care/clients/{id}/plan-instances` | 消费预览并幂等创建加入记录、计划和五项任务 |
| `GET` | `/care/clients/{id}/plan-instances` | 查询用户计划、D1–D5 和审计时间线 |
| `POST` | `/care/plan-instances/{id}/pause` | 按 `expectedVersion` 和原因暂停 |
| `POST` | `/care/plan-instances/{id}/resume` | 按 `expectedVersion` 和原因恢复并协调到期任务 |
| `GET` | `/care/tasks` | 分页查询责任范围合成任务，支持用户、计划、日序和状态筛选 |
| `GET` | `/care/tasks/{id}` | 查询冻结绑定、三轴状态和任务时间线 |

所有 POST 都要求不超过 128 字符的 `Idempotency-Key`；暂停/恢复原因必填且不超过 1000 字符。分页统一使用 `request.PageInfo.LimitOffset()`，最大 `pageSize=100`。静态契约和运行 Swagger 均已同步。

## 8. 前端页面

- `CarePlans`：只读计划模板列表/详情，醒目标明合成与生产关闭；用 D1–D5 调度轨道展示相对窗口、冻结问卷、复核和定义哈希。
- `CareTasks`：责任范围任务列表和详情；分别展示执行、时效、复核三轴，支持用户、D1–D5 和状态筛选，不提供填写或处置。
- `CareClients`：详情抽屉增加计划时间线；责任管家/医护可选择模板和明确 `anchorAt`，先预览绝对窗口再确认启动；可填写原因暂停/恢复。

前端复用统一请求封装和按钮权限，操作期间禁用重复点击并在同一次对话中复用幂等键。样式使用 UnoCSS；未使用真实通知、医疗文案或 AI 入口。

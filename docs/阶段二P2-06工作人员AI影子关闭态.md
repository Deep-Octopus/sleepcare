# 阶段二 P2-06 工作人员 AI 影子关闭态

> 执行日期：2026-08-19
>
> 覆盖需求：阶段二可选工作人员影子验证及其启用门禁
>
> 数据边界：不接收用户上下文，不创建知识或建议记录
>
> 任务结果：阶段二未选择启用，已完成可审计关闭态；工作人员影子、用户侧能力、外部模型和直接发送均未启用

## 1. 范围与非范围

### 1.1 本任务范围

- 增加 `care.ai-shadow` 配置，并把唯一合法模式冻结为 `DISABLED`。
- 增加工作人员只读准备状态，返回阶段二选择、能力开关、前置条件和稳定阻塞码。
- 增加 Router、API、Service、响应 DTO、Swagger、`SysApi` 元数据和三类工作人员只读权限。
- 保留需求与架构中未来 `AdvisorPort` 的边界，但不在输入未确认时提前实现其请求和响应结构。
- 更新模块规范、跨栈边界、业务记忆和阶段执行清单。

### 1.2 本任务非范围

- 不建立或录入知识内容，不确定知识责任人、版本、引用格式或发布流程。
- 不接模型供应商、模型 SDK、检索服务或外部网络，不发送任何用户上下文。
- 不生成 AI 建议，不实现审核、采纳、修改、拒绝、最终回复或发送谱系。
- 不新增 `KnowledgeArticleVersion`、`AISuggestion`、`FinalReply` 或其他持久化实体。
- 不实现临床、个体化、高风险、不确定和知识外问题的分类器；相应策略未批准前整个能力关闭。
- 不提供自动回复、白名单、提示词、停用开关之外的活动配置或面向用户的 AI。
- 不新增前端页面、菜单或按钮，不做页面点触。
- 不启用真实数据、真实短信或医疗内容，不提前实施 P2-07/P2-08。

## 2. 歧义处理与安全决策

阶段启动清单中的“是否进行工作人员侧 AI 影子验证”仍未确认；R2 同时规定，未启用时该 Should 不阻塞阶段二退出。当前还缺少知识责任人、经审核且版本化的知识来源、模型供应商、数据处理政策、人工审核流程、完整谱系设计、禁用场景政策和评测协议。

直接实现建议表或生成接口会隐含“已选择启用”，并提前冻结尚未批准的数据模型。因此本任务暂停向活动能力延伸，按以下决策收口：

1. P2-06 完成表示“未选择后的关闭态有代码、权限、契约和测试证据”，不表示影子验证已经运行；
2. 配置不提供测试或生产活动模式，任何非 `DISABLED` 值都阻止启动；
3. 只读接口不接收用户、咨询或自由文本输入；
4. 不实例化 `AdvisorPort`，避免出现未使用但可误接入的建议生成路径；
5. 后续明确选择时必须另行冻结范围、数据模型、状态机、权限、迁移和评测，不在本任务预设答案。

## 3. 数据模型与迁移

本任务没有业务表迁移，也没有建议状态机。仅新增两类非持久化结构：

| 结构 | 用途 |
| --- | --- |
| `config.AIShadow` | 保存单一 `mode`，当前只允许 `DISABLED` |
| `response.ShadowReadiness` | 返回关闭状态、能力开关、前置条件和阻塞码 |

初始化仅向既有 `sys_apis` 幂等登记 `GET /care/ai-shadow-readiness`。不修改咨询、互动、用户、授权、审计或通知业务表；也没有需要回填、转换或删除的数据。

## 4. 状态与能力边界

当前状态固定为：

```text
selectionStatus=NOT_SELECTED
mode=DISABLED
usageScope=NOT_ENABLED
```

以下能力全部固定为 `false`：

- 工作人员影子建议；
- 建议生成与知识检索；
- 外部模型调用；
- 面向用户的 AI；
- 直接发送；
- 经审核知识、人工审核流程和完整谱系就绪；
- 禁用场景、数据处理、评测协议和模型供应商评审就绪。

接口以稳定阻塞码逐项返回缺失条件。没有状态转换接口，也没有通过配置改变这些布尔值的路径。

## 5. 接口与权限

| 方法 | 路径 | 权限与用途 |
| --- | --- | --- |
| `GET` | `/care/ai-shadow-readiness` | 管家、医护、上级读取不可激活的关闭态和阻塞项 |

私有路由继续使用 `JWT -> MustChangePwdGuard -> Casbin -> DataScope`。Service 通过请求 Context 解析业务身份；内容管理员、普通系统管理员和缺少有效业务身份的请求失败关闭。

没有 propose、retrieve、review、adopt、reject 或 send 接口，没有客户端受限会话路径，也没有写操作和幂等键。

## 6. 配置与运行边界

仓库默认配置和 Compose 配置都显式声明：

```yaml
care:
  ai-shadow:
    mode: DISABLED
```

空值按 `DISABLED` 处理。`SHADOW`、`CONTRACT_TEST`、`PRODUCTION` 或任何其他模式都会在启动校验中失败。即使测试代码直接构造未知配置，准备状态中的所有能力开关仍保持关闭。

配置不包含供应商名称、地址、密钥、提示词、知识版本、用户字段或数据处理参数。

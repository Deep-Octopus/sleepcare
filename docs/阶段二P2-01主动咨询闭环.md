# 阶段二 P2-01 主动咨询闭环

> 执行日期：2026-08-19
>
> 覆盖需求：`CON-001`～`CON-004`
>
> 数据边界：仅使用固定测试记录，不包含真实个人数据或医疗结论
>
> 任务结果：移动端发起/补充/查看与员工端分配/回复/转交/升级/解决/关闭/重开闭环完成

## 1. 范围与非范围

### 1.1 本任务范围

- 康养用户通过已有受限会话发起在线咨询、查看本人咨询与公开互动、追加补充信息。
- 服务团队在责任或组织授权范围内查询咨询，按当前责任人完成回复、转交、升级、解决和关闭。
- 没有当前责任管家时，咨询保持待分配，由上级选择当前有效责任管家或医护。
- 每次状态变化保留互动记录、幂等凭据、事务 outbox 事实和活动待办历史。
- 移动端明确区分“随时接收”和人工回复安排，并展示正式急救/就医渠道提示。

### 1.2 本任务非范围

- 不启用真实人员、真实组织、真实个人数据或正式医疗内容。
- 不配置值班表或承诺人工响应时限；服务时段与 SLA 仍待业务方确认。
- 不接入电话平台、录音、语音转写、真实短信或其他外部通知。
- 不提供面向康养用户的 AI，也不自动生成或发送专业回复。
- 不发起满意度评价；关闭后评价属于 `P2-02`。
- 不处理设备数据范围遗留，也不提前实现日报、正式授权和试用发布。

## 2. 数据模型与不变量

### 2.1 `consultations`

咨询聚合保存用户、来源、主题、原始问题、联系顺序、当前状态、当前责任人、首次回复/解决/关闭时间、解决结果、后续安排、关闭理由和乐观锁版本。归属部门与操作人字段继续由统一 DataScope 回调盖章。

### 2.2 `consultation_interactions`

互动记录只追加、不覆盖，保存动作、操作者类型/角色、公开内容、内部原因、前后状态、目标责任角色、发生时间和幂等键摘要。移动端只读取明确标记为可见的互动，内部转交与升级原因不会越界展示。

### 2.3 一致性规则

- 每条咨询最多只有一个活动待办；转交或升级终结旧待办并创建新待办。
- 解决不会提前完成待办；关闭完成活动待办，重开创建新活动待办。
- 所有写操作都要求 `Idempotency-Key` 和当前 `expectedVersion`；相同键同请求返回原结果，相同键不同请求拒绝。
- 咨询、互动、待办、幂等凭据和 outbox 事实位于同一事务，任一步失败均不留下半成品。
- 关闭必须同时具备解决结果和关闭理由；重开清空上一轮可关闭字段，但不删除互动历史。

## 3. 状态机

`NEW → WAITING_ASSIGNMENT → ASSIGNED → HANDLING ↔ WAITING_CLIENT / WAITING_COLLABORATION → RESOLVED → CLOSED`

- 客户提交后先形成 `NEW → WAITING_ASSIGNMENT` 事实；存在当前责任管家时，同一事务继续进入 `ASSIGNED`。
- 当前责任人公开回复后可继续 `HANDLING`，也可进入 `WAITING_CLIENT`。
- 用户在 `WAITING_CLIENT` 或 `RESOLVED` 状态补充信息后回到 `HANDLING`；已关闭咨询不接受补充。
- 转交或升级进入 `WAITING_COLLABORATION`，责任人与活动待办同步变化。
- 只有授权上级可以把 `CLOSED` 重开为 `ASSIGNED`；重开前再次校验原责任人仍然有效。

## 4. 接口契约

### 4.1 康养用户受限会话

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/care/client/consultations` | 发起咨询 |
| `GET` | `/care/client/consultations` | 查询本人咨询分页 |
| `GET` | `/care/client/consultations/{id}` | 查看本人咨询与公开互动 |
| `POST` | `/care/client/consultations/{id}/messages` | 追加补充信息 |

客户端 DTO 不返回用户、机构、内部责任变化、内部原因或环境字段；受限会话不接受外部 `clientId` 扩权。

### 4.2 员工端

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/care/consultations` | 查询授权范围咨询分页 |
| `GET` | `/care/consultations/{id}` | 查看咨询详情与完整互动时间线 |
| `GET` | `/care/consultations/{id}/assignee-options` | 获取同一机构有效责任链中的可选人员 |
| `POST` | `/care/consultations/{id}/assign` | 上级分配待分配咨询 |
| `POST` | `/care/consultations/{id}/replies` | 当前责任人公开回复 |
| `POST` | `/care/consultations/{id}/transfer` | 当前责任人转交 |
| `POST` | `/care/consultations/{id}/escalate` | 管家升级给责任医护，医护升级给本机构上级 |
| `POST` | `/care/consultations/{id}/resolve` | 当前责任人记录解决结果和后续安排 |
| `POST` | `/care/consultations/{id}/close` | 当前责任人或上级关闭已解决咨询 |
| `POST` | `/care/consultations/{id}/reopen` | 上级重开已关闭咨询 |

所有 Swagger `@Success` 均落到具体响应类型；列表保持 `{ page, pageSize, total, list }`。

## 5. 权限

- 康养用户：只读写本人会话绑定的咨询，且中间件继续执行受限会话校验与写请求同源校验。
- 健康管家：读取其有效责任用户的咨询；只有作为当前责任人时才能回复、转交、升级、解决或关闭。
- 一线医护：读取其有效责任用户的咨询；当前责任人可回复、转交、升级给本机构上级、解决或关闭。
- 上级医师：在部门与下级部门范围内读取；可分配待分配咨询，作为当前责任人时处理，也可关闭已解决咨询和重开已关闭咨询。
- 普通管理员、缺少业务身份、跨机构人员、无有效责任关系人员和非当前责任人的写操作全部失败关闭。
- 菜单、隐藏详情路由和按钮权限只是交互入口；后端仍执行 JWT、强制改密保护、Casbin、DataScope、责任关系和状态机校验。

- 回退代码提交不会自动删除表或历史记录；如需物理删除必须单独审批并先完成备份。

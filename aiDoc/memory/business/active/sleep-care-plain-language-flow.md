# 睡眠康养：阶段一通俗化与流程简化

## 基本信息

- 提出日期：2026-08-19
- 当前状态：`active`
- 确认状态：用户完成阶段一功能测试后确认实施
- 需求类型：流程体验 / 文案 / 登录导航
- 优先级：P0

## 用户原始意图摘要

阶段一面向非技术人员的页面应使用通俗中文，隐藏无助于完成工作的内部编码、枚举、版本和技术说明。能由系统确定的下一步应自动完成；账号切换后必须进入当前账号有权访问的默认首页，不能沿用上一账号的页面。

## 影响范围

- 前端：阶段一员工页面、移动任务页面、登录后导航与账号状态清理
- 后端：健康管家联系后自动转交当前责任医护
- 初始化：固定机构、角色、账号和菜单采用自然业务展示名称
- 文档：关注事项流程、前后端边界与阶段一权限说明

## 已确认约束

- 页面优先展示用户要做什么、当前进度和下一步，不直接展示内部英文枚举、定义哈希、协议版本或无意义的数字标识。
- 固定隔离数据继续受内部开关和字段保护，但不要求在每个名称或页面角标中写明数据属性。
- 健康管家选择“转交责任医护继续处理”并提交联系结果后，系统在同一事务中自动完成责任人和活动待办转交；不再要求再次点击升级。
- 没有当前有效责任医护时整次提交失败并回滚，页面给出可理解的配置提示。
- 登录成功后只进入当前账号菜单中存在的默认首页；忽略登录前旧地址，清理上一账号页签状态，并重新加载当前账号动态路由。
- 不新增数据库表或字段，不新增 HTTP 接口；保留既有手工升级接口作为兼容与受控入口。
- 不加入医疗内容，不启用真实短信或面向用户的 AI。

## 当前进展

- 自动转交、缺少医护回滚和旧地址登录回归已实现并加入测试。
- 阶段一员工端、内容端、督导端与移动端的主要英文和内部技术字段已替换为通俗中文。
- 固定机构、角色和账号名称支持从旧展示值幂等更新为自然业务名称。

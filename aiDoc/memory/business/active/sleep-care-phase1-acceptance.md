# 睡眠康养：阶段一集中验收

## 基本信息

- 提出日期：2026-08-19
- 当前状态：`active`
- 确认状态：P1-11 实现与验收已经用户批准执行
- 需求类型：阶段验收 / 交付收口
- 优先级：P0

## 用户原始意图摘要

在 P1-01～P1-10 完成后，使用固定测试数据对阶段一做一次可重复的端到端验收，收口自动化、Compose、权限、浏览器证据、Git 提交和远端里程碑。

## 范围与约束

- 验收四角色主流程、通知失败分支和跨机构负向权限。
- 不新增业务模型或生产接口，不启用真实短信或用户侧 AI。
- 不使用或编造医疗内容；浏览器提交只使用非医疗流程值。
- 证据图片和 trace 只保存在已忽略的本地目录，不提交会话凭据或一次性访问原文。

## 实现与验收结果

- 新增受开关保护的固定业务时钟，所有阶段一服务共享同一时间基准。
- 修复干净 Compose 启动的系统表/业务迁移顺序，并保持初始化幂等。
- 通知失败场景的整体初始化改为事务执行，责任关系时间窗与固定时钟对齐。
- 修复固定业务时钟下客户 Cookie 寿命与 HTTP 时钟不同步的问题。
- 修复实时汇总对“恰好在当前持久化毫秒”事实的边界遗漏。
- 四角色主流程已到达 `CLOSED`，汇总在闭环后重算为未解决 `0`、已解决 `1`。
- 通知失败/未知分支保留 D1～D5，跨机构事项请求返回 HTTP `403` / 业务码 `41104`。
- `make verify`、Swagger 重生成、阶段 OpenAPI 解析、Compose 幂等启动和阶段一相关测试均通过。全仓测试仍有任务前已存在的 MCP/插件/代码生成器失败，已在 P1-11 验收记录中单独列出，本任务不扩大修改范围。

## 明确遗留

`DEV-001` / `UC-13` 尚无经批准的数据模型、状态、API 契约和独立 P1 任务。为避免在收口任务中自行发明设备领域，P1-11 只记录该缺口；项目负责人需在启动后续阶段前决定其范围和模型。

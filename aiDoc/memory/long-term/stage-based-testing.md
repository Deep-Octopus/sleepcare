# 阶段化验证偏好

## 稳定偏好

- 一个阶段尚未全部实现完成时，单个功能只做与本次改动直接相关的关键流程或功能测试
- 阶段内不为每个功能重复执行全仓测试、`make verify`、完整 Compose/迁移验收或多角色端到端回归
- 阶段内默认不做页面点触测试，也不为此索取 token、安装浏览器自动化工具或输出完整人工点触清单
- 整个阶段实现完成后，再集中执行全面自动化测试、运行环境验收和必要的页面点触测试
- 用户明确要求临时扩大验证范围时按该次要求执行；若 AI 判断最小验证不足以覆盖重大风险，必须先解释并获得确认

## 保留原因

减少阶段开发过程中的重复验证成本，把日常反馈周期保持在单功能关键路径上，同时在阶段收口时集中获得完整、可审计的验收证据。
